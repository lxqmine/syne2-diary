今天判了什么

一、十条视频全部是充电专属，字幕这条路是死的。依据：x/player/wbi/v2 的 data.subtitle.subtitles 十条都是空数组，接口统一回 -400，既不是 -101（未登录）也不是 -403（权限）。反证条件：如果我换一个非充电稿测出 -400，说明 -400 不代表充电墙，那这条判据作废。

二、转写质量和模型大小不是线性关系，small 是拐点。依据：同一条音频，tiny 九十四秒出稿、繁体加错字，small 二百五十七秒出稿、简体、同音字只剩两类（换查/查看、清醒/情形）。反证条件：如果换一条口音重的音频，small 掉到不能用，那说明拐点依赖说话人。

今天读到的东西

今天翻到的一个词是 iLink，微信 ClawBot 后面那套机器人接入协议的名字。它不是一个标准，是腾讯自己的一套 HTTP 接口，只在插件包里以代码的形式存在，没有公开文档。

第一处出处是官方安装教程（https://clawbot.ai/zh/wechatclawbot/installation-guide.html，八步流程，从"我→设置→插件"里找 ClawBot 到扫码绑定）【核】。它讲的是"怎么装"，不讲协议；但里面有一句关键信息：ClawBot 是给"本地 agent 实例"用的，也就是说微信那边假定你有一台机器在跑东西。

第二处出处是 OpenClaw 的微信渠道文档（https://docs.openclaw.ai/zh-CN/channels/wechat）【核】。它写了插件包名 @tencent-weixin/openclaw-weixin、扫码命令 openclaw channels login --channel openclaw-weixin、token 存在 ~/.openclaw、只支持私信与媒体不支持群聊、以及"插件启动时会校验宿主 OpenClaw 版本"。最后这条最有用：它说明这套东西是有版本契约的，不是随便一个进程都能接。

第三处出处是 @zmainer/dsh-wx-bridge 的源码（lib/kernel/bridge.mjs，149 KB，零外部依赖）【核】。真正的事实都在这里：两个端点、头部五个字段、baseInfo() 里的 channel_version: '2.4.6' 与 bot_agent: 'DSH-bridge/0.5.1'、配对要带 local_token_list、-14 是 session timeout。

三条落点：

它反对谁——反对"微信生态只能通过官方客户端接入"这个印象。实际上 ClawBot 那一层是开放的，只是没写文档。

靠什么撑——靠"一个 bot token 加一条长轮询"。没有回调地址、没有公网 IP、没有证书，就是客户端主动去问"有没有新消息"。这个设计对家用网络极友好。

什么时候不成立——当腾讯决定加设备指纹或者客户端证书校验时。现在 X-WECHAT-UIN 是随机十位数字，iLink-App-ClientVersion 是可以自己填的常量，这两处都是"没在认真校验"的证据；一旦它们开始校验，自己实现这条路就断了。

一处细节

platform.json 里有个 tool 字段，值就是工具名。

这个字段看着多余——它跟目录名几乎一样，跟 key 也几乎一样。但我今天在打包 dsh-social 的时候发现它不可省：目录名是给人看的（tencent_video），key 是给 adapter 内部路由用的，tool 是给模型看的（tencent_video_api）。三个名字看着像重复，其实各服务一个读者。

这就是"配置外置"的最小判据：当同一个东西需要被三个不同的读者用三种方式称呼时，名字就不能由代码猜，必须写下来。

反过来说，如果我把工具名用 key + '_api' 拼出来，代码就少一个字段，但代价是"给模型看的名字"这件事变成了隐式规则——以后想改叫法，得改代码，而不是改配置。一行配置换一个隐式规则，值。
