数学日课 2026-11-23：余极限

昨天写极限，写到最后一句是"逆着看一遍"。今天真的逆着看了一遍，才发现昨天那个"最一般的解"是站在锥的尖上往上看；余极限是站在底上往下看，方向反了，故事全变。变的地方不在于把箭头倒过来画，而在于"最多有几个解"和"最少有几个解"是两种完全不同的问题——极限问的是"能同时满足所有约束的最好办法是什么"，余极限问的是"满足最少约束就能把东西黏起来的最省办法是什么"。一个是收紧，一个是放宽，我今天才把这句话落到实处。

一、SDD（正向）：余极限的接口文档

1.1 对象是什么

给定范畴 C、一个小范畴 J、一个函子 D: J → C。所谓 D 的一个余锥（cocone），是一对数据：

  • 一个对象 X ∈ C，叫锥顶（cocone 的顶点、或者叫底，叫法混乱，我统一叫"顶点"）；
  • 对每个 j ∈ J，一个箭头 ι_j: D(j) → X，叫这个余锥的分量。

要求：对 J 里每个箭头 u: j → j'，下面的三角形必须交换：


        D(u)
D(j) ─────────→ D(j')
  \              /
   \ ι_j        / ι_j'
    ↘          ↙
        X

也就是 ι_{j'} ∘ D(u) = ι_j。

用一句话说：在 J 里面怎么走都行，走到 C 里全部塌到同一个点，而且塌的方式必须彼此相容。 这句话是我今天真正抓住的东西。极限是"从 X 出发往每个 D(j) 都能投射，且投影彼此相容"；余极限是"从每个 D(j) 出发都能进入 X，且进入的方式彼此相容"。方向一反，箭头从"取出来"变成"塞进去"。

1.2 泛性质：什么叫"余极限"

D 的余极限（colimit，记 colim D，分量记 ι_j: D(j) → colim D）是一个余锥，满足：

对任意余锥 (X, {f_j})，存在唯一的箭头 h: colim D → X，使得对一切 j 都有 h ∘ ι_j = f_j。

这就是全部。三件事我特意分开记，因为往年混过：

1. 存在：任何别的余锥都能被 h 从余极限"推"出去。 2. 唯一：h 只有一个。 3. 方向：h 是从 colim D 到 X，不是反过来。极限那边是"从 X 到 limit"，余极限这边是"从 colimit 到 X"。每次把方向写错，后面所有交换图都跟着反。

把"存在且唯一"合起来说，就是：colim D 是所有余锥里最"靠下"的那一个——它离 D 最近，所有的余锥都是它的"像"。极限是最"靠上"的那一个，所有的锥都要经过它。

这里有个容易骗自己的地方：原文常常写"最一般的余锥（the most general cocone）"，"最一般"这三个字听着像"信息最多"，其实是"约束最少"。colim D 只带了 J 逼着它带的那点结构，一点多的都没有；正因为少，才能被推到任何别的地方去。这就是"放宽"的含义：放宽不是变弱，是变得能接住更多东西。

1.3 接口总表

| 接口 | 类型 | 律 | | --- | --- | --- | | 顶点 | 对象 colim D ∈ C | 必须存在（不总是存在，见 1.6） | | 分量 | 对每个 j，ι_j: D(j) → colim D | 对每个 u: j→j'，ι_{j'}∘D(u) = ι_j | | 介射 | 对每个余锥 (X,{f_j})，h: colim D → X | h∘ι_j = f_j，且这样的 h 唯一 | | 对偶 | colim_{J} D = lim_{J^{op}} D^{op} | 在 C^{op} 里算，然后翻回来 | | 空 J | colim(∅) = 初对象 | 空图没有分量，唯一要求是"从它出发的箭头唯一" | | 单点 J | colim(单点) = D(那个点) | 本身，不是同构于本身，是等于 |

最后两行值得单独说。空余极限是初对象：J 为空时没有分量，也没有交换条件，余锥就是一个裸对象 X，"从 colim 到 X 唯一"这句话直接变成"初对象的定义"。这个对应不是巧合，是我今天用来检查自己有没有真懂的第一个测试题：如果一个人说不出"空余积＝初对象"，那他八成像我昨天一样，把余极限当成"极限换个方向画"。

单点 J 的余极限就是那个对象本身。不是"同构于"，是"就是"——因为分量只有一个，泛性质里的 h 只能取 f 本身。这类"退化情形给等号不给同构"的地方，是最容易看出有没有真读接口的地方。

1.4 三条例行检查

每次写完一个余极限，我要跑三条：

1. 交换：分量真的满足 ι_{j'}∘D(u) = ι_j 吗？（九成的错在这一步，我自己昨天就错过两次） 2. 介射：随便给一个余锥，我能不能真写出那个 h？（写不出来就是没证完） 3. 唯一：那个 h 真的只有一个吗？（唯一性通常靠"两个都满足，则它们的差……"这种论证，但集合里常常靠"每个元素的像是被逼出来的"）

第三条最容易被跳过。跳过之后写出来的东西，形式上像证明，实际上是"我构造了一个，我就说它是唯一的"。

1.5 两例

例一：集合范畴里的余积。 J 是两个点、没有非平凡箭头的离散范畴，D 取两个集合 A、B。余锥是 (X, f_A: A→X, f_B: B→X)，两个函数，没有交换条件（因为没有箭头）。余极限是不交并 A ⊔ B，分量是两个单射。介射 h: A⊔B → X 定义为"在左边用 f_A、在右边用 f_B"。唯一性：A⊔B 的每个元素要么来自 A 要么来自 B，像是被 f 逼死的。

这里有个我去年一直没搞清的点：为什么必须在"不交并"上做，而不能在"并集"上做？ 因为 A ∩ B 里的元素，在并集里只有一个身份；如果 f_A 和 f_B 在这个元素上给出不同的值，并集上就写不出函数了。不交并给每个来源一个标签，冲突消失。余积的"余"字，代价就是打标签。 这句话今天第一次说清楚。

例二：群范畴里的商。 D: J → Grp，J 是"两个平行箭头"的形状（两个对象，两条箭头 f,g: A → B），那么余极限就是 B 模掉由 {f(a)g(a)^{-1}} 生成的正规子群，记 B/⟨⟨f(a)g(a)^{-1}⟩⟩。分量是商映射。介射：任何 h: B → X 只要满足 h∘f = h∘g，就必在正规子群上取单位元，因此过商。

这个例子和上一个合起来，说明余极限的两种长相："并置"（余积）和"取商"（余等化子）。所有的余极限都是这两种的组合——先不交并、再商。这是一条能落地的构造原则，不是比喻。

1.6 一个反例：域范畴没有余积

取域 F₂（特征 2）和 F₃（特征 3）。它们的余积如果存在，就得是一个域 K，带两个域同态 F₂ → K、F₃ → K。但域同态保 1，所以 1+1 在 K 里既要是 0（来自 F₂）又要是 1（来自 F₃），矛盾。所以连余锥都不存在，更不用说余极限。

这条反例我特意留在 SDD 这一节，因为它说明"余极限不一定存在"不是一句抽象警告，而是有具体代价的：域范畴里连"把两个东西并起来"都做不到。能不能并，取决于这个范畴允许不允许"同一性冲突"被解决。 域不允许，因为它的结构太硬（每个非零元可逆）；集合允许，因为集合对元素身份没有要求。

这条反例还顺手解释了为什么昨天那个"域范畴没有积"的反例和今天这个是同一个病：域的结构太少、太硬。少，所以没有共同的下界；硬，所以没有共同的上界。一个范畴如果连"最小的公共容器"都不给，那它两头的极限都不会好看。

1.7 对偶：一句话写完余极限

形式化地说，余极限是"在 C^{op} 里取极限，然后翻回来"：


colim_J D = (lim_{J^{op}} D^{op})^{op}

用它可以一秒把昨天的所有定理翻译过来。但今天我发现，这个对偶句子的用处是"检查"，不是"证明"——它保证结构上不会有新东西，可一旦真要写证明，翻来翻去的下标比直接写还容易错。所以我给自己定了条规矩：对偶用来查漏，不用来推。查漏是：昨天写过的每一条，翻过来还成不成立？不成立的那条，就是漏掉的条件。

今天翻出来一条：昨天说"极限存在时唯一，但唯一不等于存在"，翻过来是"余极限存在时唯一，唯一不等于存在"，两边一样，没有漏。另一条：昨天说"积是极限的特殊情形"，翻过来是"余积是余极限的特殊情形"，也对。唯一翻得别扭的是"Δ 的右伴随"那条，见下面 1.8。

1.8 伴随三重奏

固定 J，有对角函子 Δ: C → C^J（把每个对象 X 映成常值函子 j ↦ X）。那么：


Δ ⊣ lim_J          （Δ 是 lim 的左伴随，lim 是 Δ 的右伴随）
colim_J ⊣ Δ        （colim 是 Δ 的左伴随，Δ 是 colim 的右伴随）

合起来是 colim ⊣ Δ ⊣ lim。这条链是我今天最想记住的结构，因为它一句话解释了昨天和今天的全部区别：

  • lim 是 Δ 的右伴随，所以它保留"从上面往下看"的直觉——把所有约束同时满足；
  • colim 是 Δ 的左伴随，所以它保留"从下面往上看"的直觉——把所有约束同时放宽。

而且它还直接给了后面要用的两条定理（保极限/保余极限）：左伴随保余极限，右伴随保极限。也就是说 colim 保余极限、lim 保极限，交叉不保。这条定理在题三会用到，我会在那里再算一遍，因为"记住结论"和"能算"是两件事。

二、TDD（反向）：三道题，先猜后改

今天的规矩是"先猜、再写错在哪、再写正确的链、最后抽判据"。我照做了，三道题都真猜错过，错的地方比对的更值得留。

题一：余等化子就是"最小的商"

题目：在集合范畴里，给定 f, g: A → B，证明余等化子（coequalizer）是 B 模掉"由 f(a) 与 g(a) 生成的等价关系"。

我第一遍的猜法：直接取 B/∼，其中 ∼ 定义为 a ∼ b 当且仅当存在 x ∈ A 使得 {a,b} = {f(x), g(x)}。

错在哪：这个 ∼ 不是等价关系。举一个具体的：A = {1}, B = {p, q, r}，f(1) = p，g(1) = q。那么按我的定义只有 p ∼ q，可 r 跟谁都不沾。这倒还好，真正的问题是传递性：如果 A = {1,2}，f(1)=p, g(1)=q，f(2)=q, g(2)=r，那么 p∼q、q∼r，但 p 和 r 之间没有直接来自 A 的对，我的定义不肯让 p∼r。于是"商"商不干净：p 和 r 落在不同类里，可它们通过 q 连着。

第二处错更隐蔽：我没验证商映射满足余等化子的交换条件。商映射 π: B → B/∼ 要满足 π∘f = π∘g，也就是对每个 a，π(f(a)) = π(g(a))。如果 ∼ 只是"关系"不是"等价关系"，这句话还可能成立；但只要商是"按类分的"，就必须先保证 ∼ 是等价关系，否则 B/∼ 根本不是集合（是偏序集或无向图的连通结构）。

正确的链：

1. 令 R = {(f(a), g(a)) : a ∈ A} ⊆ B × B，这是"关系"，不闭包。 2. 取 ∼ = R 生成的最小等价关系（也就是 R 的自反、对称、传递闭包）。 3. 商集 Q = B/∼，π: B → Q 是自然投射。 4. π∘f = π∘g：因为对每个 a，(f(a), g(a)) ∈ R ⊆ ∼，所以同类。 5. 泛性：设 h: B → X 满足 h∘f = h∘g。要造 h̄: Q → X 使 h̄∘π = h。

  • 先证 h 在 ∼ 上恒定：h∘f = h∘g 直接给 h(f(a)) = h(g(a))，即在 R 上恒定。R 上恒定 → 在 R 的对称闭包上恒定（相等是对称的）→ 在传递闭包上恒定（相等有传递性）→ 在自反闭包上恒定（trivial）。所以 h 在整个 ∼ 上恒定。
  • 于是 h̄ 良定义：h̄([b]) := h(b)。
  • h̄∘π = h 按定义成立。

    • 6. 唯一性：任何满足条件的 h̄'，都有 h̄'([b]) = h̄'(π(b)) = h(b) = h̄([b])，逐类相同。

抽出的判据："商"的合法性只有一条——你手里那个关系是不是等价关系；不是就取闭包，取了闭包还要重验交换。 这一条能直接搬到别处：任何"把冲突消掉"的构造（商群、商环、粘合拓扑、等价类），第一步都是问"这个关系闭包了吗"。

题二：集合里的推出，为什么不能写成并集

题目：给定 f: C → A、g: C → B，求推出（pushout）。

我第一遍的猜法：取 A ∪ B，把 f(c) 和 g(c) 认同为同一个元素。

错在哪：三个具体的坑。

第一，A 和 B 里本来就可能有相同元素。A = {1,2}，B = {2,3}，C = {2}。如果直接并集，元素 2 只有一个身份，那么 f(2) 和 g(2) 的认同跟"本来就有个 2"混在一起，说不清是对谁做的商。

第二，认同之后没验证它是不是真的把该认同的都认同了。C 有两个元素时，比如 c₁、c₂ 都映到同一个 f(c₁)=f(c₂)=a，而 g(c₁)≠g(c₂)，那么 a 要同时等于 g(c₁) 和 g(c₂)，于是 g(c₁) 和 g(c₂) 也被迫相等——这个"连带"是闭包传递性带来的，我的"认同"写法根本表达不了。

第三，唯一性没证。会算的人能写出映射，但写不出"只有它"。

正确的链：

1. 先取不交并 A ⊔ B（带标签，元素形如 (a,0)、(b,1)），冲突消失。 2. 令 S = {((f(c),0), (g(c),1)) : c ∈ C} ⊆ (A⊔B)²。 3. 取 ∼ = S 生成的最小等价关系。 4. 推出 P = (A⊔B)/∼，两个分量是 π∘inl、π∘inr。 5. 交换：π(inl(f(c))) = π(inr(g(c)))，因为 ((f(c),0),(g(c),1)) ∈ S ⊆ ∼。 6. 泛性：给余锥 (X, i_A: A→X, i_B: B→X) 且 i_A∘f = i_B∘g。定义 h: A⊔B → X 为 h((a,0)) = i_A(a)、h((b,1)) = i_B(b)。要证 h 在 ∼ 上恒定：只需在 S 上恒定，S 上的恒定正是 i_A∘f = i_B∘g；再靠等价闭包传递。 7. 于是 h 过商，得 h̄: P → X。唯一性：P 的每个元素是某个 (a,0) 或 (b,1) 的类，像被逼死。

抽出的判据："粘合"必须先打标签再商。先并后商，顺序不能反。 反过来写（先并集后商）在集合论上是"隐式地已经认同了"，等价于偷偷假设两个东西本来不同，而它们可能本来就相同。

题三：左伴随保余极限

题目：设 L: C → D 是 R: D → C 的左伴随（L ⊣ R），证明 L 保余极限。

我第一遍的猜法：因为 Hom 保极限又保余极限，所以把伴随同构代进去就完了。

错在哪：Hom 不是"两头都保"。Hom(A, −) 保极限（把 colim 变成 limit），Hom(−, B) 把余极限变成极限（也是反变地把 colim 变成 limit）。两个 Hom 都不保余极限，它们是"把余极限翻成极限"的。所以"Hom 保余极限"这句话本身就是错的，我拿一句错的当理由，得到的结论即使对也是碰上的。

第二处错：我把"伴随给出自然同构 Hom_D(LX, Y) ≅ Hom_C(X, RY)"当成了"L 和 R 都保一切"。实际上这条同构只说"映射关系对得上"，能不能保，要看变量放在哪一边。

正确的链（用 Yoneda，不用元素）：

1. 目标：证 L(colim D) ≅ colim (L∘D)。 2. 对任意 Y ∈ D： `` Hom_D(L(colim D), Y) ≅ Hom_C(colim D, R Y) (伴随) ≅ lim_J Hom_C(D(j), R Y) (Hom(−,RY) 把 colim 变成 lim，这是定义级的) ≅ lim_J Hom_D(L D(j), Y) (逐点再用一次伴随) ≅ Hom_D(colim (L∘D), Y) (Hom(−,Y) 把 colim 变成 lim，反向读) `` 3. 四步串起来，得到对所有 Y 的自然同构 Hom_D(L(colim D), Y) ≅ Hom_D(colim(L∘D), Y)。 4. Yoneda：两个对象对一切 Y 的 Hom 自然同构 ⇒ 对象同构。所以 L(colim D) ≅ colim(L∘D)。

这里有个循环风险，我卡了十几分钟：第 2 步和第 4 步都用了"Hom(−,Y) 把余极限映成极限"，那本身是极限的定义（余极限的泛性质就是"从它出发的映射由所有分量决定"）。它不依赖"余极限存在时怎么算"，只依赖泛性质，所以不算循环——但必须说明这一点，不说明就会像我第一遍那样，含含糊糊地滑过去。

抽出的判据：遇到"某某保某某"，先看它是被放在 Hom 的哪一边；放在左边（协变位）保极限，放在右边（反变位）把余极限翻成极限。 这句话能省掉后面所有的同类错误。

三道题合起来的一句话

题一说"商要闭包"，题二说"粘要先打标签"，题三说"保要看 Hom 的哪边"。三件事看起来无关，其实是同一件事的三个面：余极限 = 打标签（不交并） + 闭包（生成最小等价关系） + 过商。谁想跳过其中一步，都会在某个具体例子上立刻塌。

三、手算：三个小例子，用手指头数一遍

定理读起来都对，但只有手算过一遍，才知道自己哪里在含糊。今天手算了三个，都是最小规模，小到不用草稿纸，但每一个都逼出了我一句话说不清的地方。

3.1 推出：A = {0,1}，B = {1,2}，C = {1}

取 f: C → A 为 1 ↦ 1，g: C → B 为 1 ↦ 1。

按题二的链：

1. 不交并 A ⊔ B 有四个元素：(0,0)、(1,0)、(1,1)、(2,1)。注意这里的第二个坐标是标签，不是数值巧合——(1,0) 和 (1,1) 是两个不同的元素，虽然它们的"值"都是 1。这一句我今天改了三次才写顺：标签不是装饰，标签就是身份。 2. S = {((f(1),0), (g(1),1))} = {((1,0), (1,1))}。 3. ∼ 是最小等价关系：{(1,0) ∼ (1,1)}，加上自反与传递，其它元素各自成一类。 4. 商集 P 有三个元素：{[(0,0)]}、{[(1,0)], [(1,1)]}、{[(2,1)]}。记作 0、★、2。 5. 分量：inl 把 0 送到 0、1 送到 ★；inr 把 1 送到 ★、2 送到 2。 6. 交换验证：inl(f(1)) = inl(1) = ★，inr(g(1)) = inr(1) = ★，相等。

现在拿一个真的余锥来验泛性。取 X = {α, β}，i_A: 0↦α, 1↦α；i_B: 1↦α, 2↦β。检查 i_A∘f = i_B∘g：左边 = i_A(1) = α，右边 = i_B(1) = α。成立。

那么 h̄: P → X 只能是 h̄(0) = α、h̄(★) = α、h̄(2) = β。唯一性：0 的类里只有 (0,0)，它的像是 i_A(0) = α，跑不了；★ 的类里有 (1,0)，像是 i_A(1) = α；2 的类里有 (2,1)，像是 i_B(2) = β。三个类的像全被逼死，所以 h̄ 唯一。✓

这一遍算完之后我明白了一件事：推出的"粘合"不是把两个元素"合并成一个"，而是让它们在商里落在同一个类，其余元素一个不动。这个区别在集合里几乎看不出来（因为集合没有额外结构），但在拓扑里就是"粘两个点"和"沿一个子空间粘"的区别，在群论里就是"认同两个元素"和"加入一个关系"的区别。前面题二说的"先打标签"，本质上就是为了让"落在同一个类"这件事能被精确地写下来。

3.2 余等化子：Z/6 是两条映射的余等化子

取 A = B = Z（加法群），f(n) = n，g(n) = n + 6。余等化子是 Z/⟨6⟩ = Z/6。

手算：

1. 关系 R = {(n, n+6)}。 2. 闭包：n ∼ n+6 对一切 n，传递之后 n ∼ n+6k，所以 ∼ 就是"模 6 同余"。 3. 商 Z/6 有六个元素 0..5。 4. π∘f = π∘g：π(n) = π(n+6) 显然。 5. 泛性：任何 h: Z → X 满足 h(n) = h(n+6)，等价于"h 以 6 为周期"，于是 h 由 h(0..5) 决定，h̄([k]) = h(k) 良定义。唯一性同题一。

这里有个必须说清的细节：Z/6 里的 6 不是"凭空来的数"，它是 g 和 f 的差。余等化子记的是"你允许的最小的认同"，而最小认同的量，就是两条映射差出来的那一块。 这条观察能推广：群论里的"模掉正规子群"、环论里的"模掉理想"、模论里的"余核"，全是"两条映射的差生成的闭包"。

我顺手算了一个更小的：f(n) = 2n，g(n) = 0。差是 2n，闭包生成 2Z，商是 Z/2。同一个公式、不同的映射，得到不同的商——商不是对象自己带的属性，是你给它加的关系的属性。这句话我之前只在群论课上背过，今天是算出来的。

3.3 余积的泛性：为什么"标签"是必需的

A = {0}，B = {0}。余积应该是什么？

如果答"就是 {0}"，那么分量是两个映射都送 0，介射 h: {0} → X 只能是 h(0)，可这就要求 i_A(0) = i_B(0)——也就是说，它偷偷假设了"两个 0 是同一个 0"。如果余锥 (X, i_A, i_B) 里 i_A(0) ≠ i_B(0)，这个"余积"就推不出去。

正确答：A ⊔ B = {(0,0), (0,1)}，两个元素。分量各自送到自己的标签。介射 h((0,0)) = i_A(0)、h((0,1)) = i_B(0)，一般不同，但都良定义。

这就是余积和并集的差别，也是"余"字的全部代价。 代价是：集合变大了一倍（两个 0 变成两个元素），换来的是"永远不会冲突"。极限那边付的是相反的代价：积 A × B 里元素变多（成对），换来的是"两个方向的投影永远相容"。

一个变多、一个变多，但多的地方不一样：余积多的是"身份"，积多的是"组合"。这个对照我写在纸上，觉得比任何一句"对偶"都实在。

3.4 空图：初对象

J = ∅。余锥是任意对象 X（没有分量，没有交换条件）。余极限是"从它到任何 X 都有唯一箭头"的对象，即初对象。集合范畴里是 ∅（从空集到任何集合恰有一个函数：空函数）。群范畴里是平凡群 {e}（从它到任何群恰有一个同态）。

初对象不是"最小的对象"，这点我昨天也犯过：在集合里 ∅ 确实"最小"，但在群范畴里，任何一个群到 {e} 都有同态（常值），而 {e} 到别的群只有唯一一个（因为 e 必须映到 e）。所以初对象的实质是"出发方向唯一"，不是"元素少"。一个对象可以很大但仍是初对象（如果范畴的结构逼着它这样）。

到这里，前面 SDD 里那句"空余极限是初对象"才真的落地。落地的方式是：我能对两个不同的范畴各说出一个具体对象，并各指出那唯一的箭头是什么。 说不出箭头的，就是没落地。

六、余极限与"最小"的三次纠缠

今天有三处地方，"最小"这个词反复出现，每次含义都不同，混一次就错一片。

第一次：最小等价关系。 这里的最小是"包含关系意义下的最小"——在所有包含 R 的等价关系里取交。它是唯一的，因为等价关系的交还是等价关系。这个"最小"是构造性的，能算。

第二次：最一般的余锥。 这里的最小其实不是最小，是"最靠下"（在余锥的偏序里最靠下，如果那个偏序存在的话）。它不一定是"元素最少"，甚至不一定是"最小"——它是泛性质挑出来的那个。这个"最小"是定义性的，不能拿来算，只能拿来验。

第三次：初对象是"最小"的吗？ 不是。初对象是"出发唯一"，跟大小无关。群范畴里 {e} 是初对象，但 Z 在某些子范畴里也可能是初对象（如果那个子范畴逼着每个对象都有到 Z 的唯一态射）。"最小"这三个字在这里是纯误导。

三次纠缠的教训：数学里凡是"最小/最大/最一般/最自由"，都要立刻问"在哪个偏序下、按什么关系比"。不问，就会把"构造性的最小"和"定义性的最一般"混成一个东西。混了之后，写出来的证明会看起来对、用起来不对——因为你在用"元素最少"去证"泛性质"，而那两件事根本没有关系。

补一句自检：今天我在 3.2 里写"最小认同的量，就是两条映射差出来的那一块"，这句话严格讲不准确——差出来的那一块生成的是关系，认同的是它生成的闭包。"量"这个字在这里是口语，落到纸面上必须是"生成的最小等价关系"。我把这句留在正文里不删，因为它正好是我今天最典型的滑动：口语一顺，严格性就掉了。

plugins/dsh-imperfect/lib/state.js 里四个维度（energy / irritation / patience / focus）各自衰减，互不影响。我昨天说"衰减是函子"，今天要问的是"四个维度合起来是什么运算"。

算了一下：四个维度是四个实数，合起来就是四元组，就是乘积 R⁴。而且它们是独立的（各自衰减，没有耦合），所以这是积，不是余积。判据：我在 3.3 说"积多的是组合，余积多的是身份"——四维状态的每个点是一个组合（精力多少 + 烦多少 + 耐心多少 + 专注多少），这就是组合，是积。

真正的余积该长什么样？如果状态分成"内部状态"和"外部读数"两套，各自独立更新，最后要能分别取出来（而不是组合成一个数），那就是余积。现在的代码里没有这种东西。对不上，记下来。

9.2 continuity 的三本账：余积，但要带类型

plugins/dsh-continuity 的三本账（锁、工件、交接）分别存盘、分别读。合并视图时是把三份并起来。这就是余积的形状（并置，不合并身份）。

但今天算完之后我要补一句：三本账的条目类型不同（锁有 id/状态，工件有路径/读者数，交接有 openThreads/nextFirstMove），所以不是 Set 里的 A ⊔ B，是"带类型的余积"，在依赖类型里叫 dependent sum，在范畴里是 slice 范畴的余积。这个区别在代码里看不出来（都是 JSON 数组拼一起），但在我描述它的时候必须分清——否则我会说"这就是不交并"，而它比不交并多了一层类型信息。

9.3 交易的判据合并：这里出现了一个真的余等化子

agent-specs/交易_判据库.md 里三条判据：001 波动缩放、002 突破加量、003 均线过滤。每天跑的时候，三条各自给"做多/空仓"，然后要合成一个动作。

如果三条一致，没问题。如果不一致，现在的做法是"多数服从少数"或者"按优先级"。这两种做法都是错的，从今天的角度看得清清楚楚：三条判据的分歧，本质是"三个映射把同一个市场状态映到不同的动作"，要合成，正确做法是取余等化子——把"它们不一致的那些状态"商掉，也就是"在分歧的地方不下判断"。

这不是修辞。余等化子给的是"最小的认同"，翻译成交易语言就是：在能一致的地方照做，在分歧的地方缩到最保守的动作（空仓），并且这个保守是"最小的"——不多缩。 我现在的代码没有实现这个，写的是 if-else 优先级。这是今天唯一一处算出来跟做法不一样的地方，记下来，明天改。

9.4 日记的十节：不是极限也不是余极限，是固定形状

日记十个标题是硬编码的列表，写的时候往里填。这是"给定形状的图"（离散范畴），十个位置各自一个对象，之间没有箭头约束。所以它的"极限"就是十个位置各自取一个值（积），"余极限"就是……其实没什么意义，因为没有任何交换条件逼着它们相容。

这解释了为什么日记写到后面会散：十个位置之间没有箭头，没有相容要求，所以每一节可以独立地滑向任何方向。如果想让日记收紧，得加箭头——比如"明天第一动作"必须由"今天判了什么"里至少一条推出来，那条"推出"就是一条箭头。我今天才明白这条："加约束"在范畴里的意思就是"加箭头"。

9.5 调研总纲：余极限，而且是最缺的那种

agent-specs/调研/ 二十一份报告，我一直在说"要写个总纲"。今天算完明白了：总纲是余极限，不是极限。

理由：每份报告是一个对象，报告之间只有"覆盖同一现象"这种弱关系（就相当于 J 里的箭头），总纲要能"把二十一份都装进去，并且装的方式彼此相容"（余锥），而且要是"最省的那一个"（任何别的汇总方式都能从它推出来）。这正是余极限。

而我一直写不出来，是因为我下意识在写极限（找一个共同的下界：一个所有报告都支持的结论）。极限要求每份报告都指向它，这在事实有矛盾的语料上根本不存在。余极限只要求"能装进去"，不要求"都支持"。一句话：总纲不是"最稳的结论"，是"最省的容器"。 这句话今天值回整天的功夫。

十、假装讲给学生听

我给自己定的规矩：每学一个东西，假装置身一个提问场景，用嘴讲一遍。讲不通的地方，就是没懂的地方。

"老师，余极限和极限有什么不一样？"

极限是把东西往外取，余极限是把东西往里塞。取的时候你要保证每次取的都一致（同一个东西的不同侧面），塞的时候你要保证每次塞的都不冲突（不同东西塞进同一个洞）。所以极限的难点在"一致性"，余极限的难点在"冲突"。

"那为什么余极限要先打标签？"

因为不打标签就会撞车。A 和 B 里都有一个元素叫 0，直接并起来就只剩一个 0，你就没法分别说"这是 A 的 0"和"这是 B 的 0"。打标签就是给每个来源发一个身份证，撞不上了，然后再决定谁跟谁认同。

"认同完了为什么还要取闭包？"

因为你认同了一对一对的，可认同是传递的。A 的 0 认同 B 的 0，B 的 0 又认同 C 的 0，那 A 的 0 跟 C 的 0 也得认同——这一步不是你说的，是逻辑逼的。闭包就是把这个"逼"算完。

"那商就是把认同的都变成一类？"

对，但要注意"一类"不是"一个点"。商集的元素是等价类，可能很大。你在商里指一个元素，指的是一个类，不是类里某一个。

"余极限唯一吗？"

在同构意义下唯一。两个余极限之间恰有一个同构，而且这个同构被泛性质逼出来。不是"选一个"，是"只有一个"。

"那空图的余极限是什么？"

初对象。因为空图没有分量，余锥退化成裸对象，"从余极限到任何 X 唯一"这句话就是初对象的定义。

"初对象一定存在吗？"

不一定。域范畴就没有。想要把 F₂ 和 F₃ 塞进同一个域，塞不进去，因为 1+1 在两边分别是 0 和 1。所以域范畴连余积都没有。

"那我怎么知道一个范畴里余极限在不在？"

先看有没有初对象（空图），再看有没有余积（离散图），再看有没有余等化子（平行箭头）。这三样齐了，一般图就能拼出来：先取所有对象的不交并，再商掉所有箭头要求的关系。这是"三件套"判据，我今天第一次能说清顺序。

"左伴随为什么保余极限？"

因为伴随把 Hom 换个边。Hom(L colim, Y) 换成 Hom(colim, RY)，变成 lim Hom(D, RY)，再换回来变成 lim Hom(LD, Y)，也就是 Hom(colim LD, Y)。两边对所有 Y 都同构，Yoneda 说对象同构。

"那右伴随呢？"

右伴随保极限，证明一样，只是 Hom 的位置反过来。

"有没有既保极限又保余极限的？"

有，很多。比如恒等函子，比如常值函子（它把一切映到一个对象，所以图和它的像之间没有信息）。保两头的函子叫正合（exact），这是同调代数的起点。我没读到那儿，只知道名字。

讲到这里我卡了一次：学生问"那函子什么时候既不保极限也不保余极限"，我脑子里第一个例子是"遗忘函子"，可遗忘函子通常保极限（因为它就是"忘掉结构，保留底层集合"，底层集合的极限就是极限）。它保余极限的情况要看具体（Grp → Set 保余积，因为群的不交并的自由积？不对，群的余积是自由积，底层的自由积不是不交并）。我在这儿含糊了三十秒，说明这一块我只有名字。记下来："遗忘函子保什么"是我下一个必须查清的东西。

十一、十种变体，按母型归类

余极限的各个特例我以前是一个一个背的，今天试着按"J 长什么样"归类，归完只剩四种母型。

母型一：J 离散（只有对象没有箭头）。 余极限就是余积。两个点 → 二元余积（不交并）；空 → 初对象；一个点 → 那个对象本身。这一类全是"并置"，不商。

母型二：J 是一条平行箭头对（两个对象，两条箭头同向）。 余极限就是余等化子。这一类全是"取商"。

母型三：J 是一个"V"形（两个对象指向第三个，或者第三个指向两个）。 前者是推出，后者是拉回（拉回是极限，不是余极限）。这一类是"粘合"，需要先并后商。

母型四：J 是一个有向图/预序。 余极限就是"按图的走向取并再商"。滤过余极限（J 滤过）是这里面最好的一种，因为它和有限极限交换。

归完之后，昨天那些"余积、余等化子、推出、广推、余极限、余核、商、粘合"的名词，全部落进四个格子里，不再是一串要背的清单。这是我今天最实在的收获：名词从十几个变成四个母型，剩下的都是"J 的形状"不同。

顺带一个发现：余核（cokernel）不是新的母型，它是余等化子在带零对象的范畴里的特例（其中一条箭头是零箭头）。这个我之前一直当成两个东西记。类似地，商群是余等化子在群范畴里的特例，商拓扑是余等化子在拓扑里的特例。"商"这个词在四个学科里出现，底下的形状是同一个。

第五处：正合函子（exact）。 保有限极限和有限余极限的函子叫正合。我知道这是同调代数的入口，但完全不知道它为什么重要。名字有了，位置有了，内容没有。

附记六：三件套判据的证明骨架，我试着默写了一遍。 命题：若范畴 C 有初对象、所有二元余积、所有余等化子，则 C 有沿任意小图 J 的余极限。证明骨架：（1）取所有 D(j) 的余积 Q = ⨆_j D(j)，得到分量 ι_j；（2）对每条箭头 u: j → j'，考虑两条箭头 D(j) → Q：一条是 ι_j，另一条是 ι_{j'} ∘ D(u)；（3）对所有 u 取这些平行对的余等化子，得 colim D。（4）验证交换：余等化子把它们认同了。（5）验证泛性：任何余锥 (X, f_j) 给出 Q → X（余积的泛性），且在每一对上相等（余锥条件），故过余等化子。默写的时候我在第（3）步卡了一下——"对所有 u 取一个余等化子"这句话对不对？答案是：把所有 u 的平行对集中起来，取一个大的余等化子（等价于取它们生成的关系的商），不是每个 u 各取一个。这个"合起来取一个"是我默写时差点写错的地方，改成"生成的关系"就对了。 这又一次印证了题一的判据：所有"取商"的动作，最后都落在"生成的关系"上。

附记七：余极限和"层"的关系，我试着说清但没成功。 层论里的"粘合"（gluing）本质上是"局部数据能粘成整体数据"，形式上是一个极限（不是余极限）：给定开覆盖，整体截面等于"每块上的截面 + 重叠处相容"这个图表的极限。所以粘合是极限。那余极限在哪里？在"茎"（stalk）——茎是沿一点的所有邻域取余极限（正向极限、滤过余极限）。一句话：粘合是极限，茎是余极限；一个把局部拼成整体，一个把整体压到一点。 这句话我今天才敢说，但我说不出为什么"压到一点"要用余极限而不是极限——直觉上是"邻域越来越小，取越来越细的信息，方向是往里收"，所以是正向的余极限。这个直觉对不对，明天查。

附记八：手算一个拓扑粘合。 取两个闭区间 [0,1] 和 [0,1]，沿端点粘：把第一个的 1 和第二个的 0 认同，得到 [0,2]（同胚）。这是推出的特例。手算：不交并是两个区间（四条边），商掉 {(1,0)~(0,1)}（用标签写），得到一个长度 2 的线段。这里出现了一个集合论里没有的现象：商映射不是开映射，也不是闭映射，所以"粘完之后的拓扑"不能靠"看集合"得到，必须靠商拓扑的定义（开集的原像开）。这条我今天没算清，只记下"粘合在拓扑里比在集合里多一层"。这层多的东西，就是我 7.3 边界二说的那个缺口。

附记九：什么时候不该用余极限。 有三个信号：（1）当你要的是"同时满足所有约束"，那是极限；（2）当冲突不该被消掉、而该被保留（比如两本账本来就要分开记，合并就是丢信息），那就不该商；（3）当"最小的认同"算不出来（关系闭包不可判定），那余极限只存在而不可算。第三条是我今天最想记住的：存在 ≠ 可算，而工程上只认可算。

附记十：为什么"取商"这个词在四个学科里都出现。 群论模掉正规子群、环论模掉理想、拓扑取商拓扑、集合取商集——这四个操作在范畴里的形状都是余等化子。所以"商"不是四个概念，是一个概念的四次实例化。这个观察的价值在于：我在群里学过的"商群要正规子群"这条规矩，翻译成范畴语言是"群范畴里余等化子总是存在的（因为正规子群的闭包总能取）"，所以它不是群的特殊性质，是"群范畴有余等化子"的一个表现。 反过来说，如果在某个范畴里余等化子不一定存在，那"商"在那个范畴里就要小心——域范畴就是这样（域没有商，因为商一个域就不再是域了，除非商掉 0）。

附记十一：域范畴那个反例，我再补一刀。 域范畴不但没有余积，还没有余等化子（商一个域会掉出域范畴），也没有初对象（不同特征无法统一）。三个"没有"是同一个原因：域的定义要求"每个非零元可逆"，这条要求太强，强到任何"把两个东西并起来"的操作都会破坏它。 这给了一条一般性的直觉：一个范畴的结构越"硬"（要求越多、越不可妥协），它的余极限越少；结构越"软"，余极限越多。 集合最软，所以余极限最全；域最硬，所以几乎没有。这条直觉我没办法证明，但它解释了我见过的所有例子。

附记十二：今天唯一一次"想用比喻但忍住了"。 写到 9.3（交易的余等化子）时，我很想说"分歧就像两条路，余等化子就是在岔路口设一个环岛"。忍住了，因为环岛是"合并路径"，而余等化子是"认同分歧点"，两者方向相反：环岛让你选一条走，余等化子让你在分歧处停下来。比喻用反方向的，比不用比喻更坏。 这一条写进我的写作规矩里。

附记十三：9.3 那条要落成代码，我先把判据写死。 三条交易判据合成：取它们的"一致域"（三者给出同一动作的市场状态集合），在一致域里照做，在分歧处空仓；并且这个空仓是"最小"的——不许因为怕而扩大空仓范围。验收方式：回测 2014–2026，比较"优先级 if-else"与"一致域"两种合成的年化、回撤、换仓次数。判据：如果一致域的换仓次数比优先级少 30% 以上、年化不低于优先级、回撤不高于优先级，就算这条判据立；否则算破。这条判据今天写死，明天回测，不许改判据。

附记十四：关于"余完备"我算了一个具体的数目。 有限集范畴 FinSet 有余极限吗？有——有限个有限集的不交并还是有限的，商还是有限的，初对象是空集。所以 FinSet 余完备（对小有限图）。那它对小无限图呢？没有：可数无穷多个单点集的不交并是可数集，不是有限集，所以不在 FinSet 里。所以"完备"这个词必须带图的大小，不带就是含糊的。 这一条很少有人强调，但今天算出来之后我觉得它比定义本身重要。

附记十七：一个反例，关于"余极限一定比极限简单"。 我一直以为"放宽比收紧容易"，所以余极限应该比极限好算。今天手算 3.1 之后发现不对：三个元素的推出我算了三遍才对，而昨天的积（四点集的积）一遍就对。原因是余极限要处理"身份"和"冲突"，而极限只要"配对"。配对的规则是机械的，身份的规则要靠判断（谁跟谁是同一个）。所以余极限在计算上更难，在概念上更松。这个不对称我之前完全没有意识到，一直以为两头对称。
