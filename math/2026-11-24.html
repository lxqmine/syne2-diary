一、SDD：单子的接口文档

1.1 对象是什么

一个单子，写成一个三元组 (T, η, μ)，其中：

  • T 是一个自函子，T : C → C。意思是：对范畴里每个对象 A，它给一个对象 TA；对每个箭头 f : A → B，它给一个箭头 Tf : TA → TB，并且保住恒等与复合。
  • η（eta，单位）是一个自然变换，η : Id ⇒ T。对每个对象 A，给一个箭头 η_A : A → TA。
  • μ（mu，乘法）是一个自然变换，μ : T² ⇒ T。对每个对象 A，给一个箭头 μ_A : TTA → TA。

先说清楚为什么要长这样。T 的意思是"把一个东西包进某种上下文里"：包进"可能失败"，包进"有状态"，包进"有很多个结果"。既然包了一层，就会遇到两个问题：

1. 一个裸值怎么进这个上下文？——这就是 η。 2. 两层上下文怎么压成一层？——这就是 μ。

所以 η 和 μ 不是拍脑袋加的，它们是"包起来"这个动作必然带来的两个接口。第三个问题是"包起来之后还能不能接着算"，那是 T 作为函子的职责（Tf）。

1.2 接口清单

| 接口 | 类型 | 直觉 | |---|---|---| | T（对象部分） | A ↦ TA | 把一个类型包进上下文 | | T（箭头部分） | f : A → B ↦ Tf : TA → TB | 上下文里的东西也能被函数作用 | | η_A | A → TA | 裸值进上下文（return、pure、unit） | | μ_A | TTA → TA | 两层压一层（join、flatten） | | fmap | 由 T 给出 | 就是 Tf | | bind（派生） | TA → (A → TB) → TB | bind(m, f) = μ_B(Tf(m))，也就是先 fmap 再压平 |

这张表里只有 T、η、μ 是原始接口，fmap 和 bind 是派生的。这一点很关键：编程语言里习惯把 bind 当主角（>>=），数学里把 μ 当主角。两者等价，但证明的方向不同——用 bind 证明时，容易把"结合律"当成一条独立公理；用 μ 证明时，会发现结合律其实是"三层压成一层有两条路，而这两条路必须一样"。

1.3 三条律

左单位律：μ_A ∘ T η_A = id_{TA}。

意思是：把裸值包进去（η），再和已有的那层压平（μ），什么都不该变。用 bind 说就是 bind(η(a), f) = f(a)。

右单位律：μ_A ∘ η_{TA} = id_{TA}。

意思是：在已经包好的东西外面再包一层（η_{TA}），然后压平，也不该变。用 bind 说就是 bind(m, η) = m。

注意左右两律的区别在"包在哪一侧"：左律是把裸值先包起来，右律是把整个 TA 再包一层。这两条不是同一条的翻版，写反了就会得到错误的单子。

结合律：μ_A ∘ μ_{TA} = μ_A ∘ T μ_A。

意思是：有三层 TTTA，先压里面那两层再压外面（左边），和先压外面那两层再压里面（右边），结果必须一样。画成方块就是：


TTTA --T μ_A--> TTA
  |               |
 μ_TA            μ_A
  v               v
 TTA --μ_A-----> TA

这个方块交换，就是"结合律"的全部内容。它看起来像一句废话（压平当然应该一样），但它是一条硬要求：不是所有"看起来能压平"的构造都满足它。

1.4 例子一：List（不确定数量的结果）

  • TA = List(A)，一个 A 的列表。
  • Tf：对每个元素应用 f，保持顺序。这就是 map。
  • η_A(a) = [a]，单元素列表。
  • μ_A：把列表的列表拼成一个列表。[[1,2],[3]] ↦ [1,2,3]。

验三条律：

  • 左单位：μ(T η([a]))，T η([a]) = [[a]]，压平得 [a]。对。
  • 右单位：μ(η_{TA}([a,b]))，η_{TA}([a,b]) = [[a,b]]，压平得 [a,b]。对。
  • 结合律：[[[1],[2]],[[3]]]，先压里面得 [[1,2],[3]] 再压得 [1,2,3]；先压外面得 [[1],[2],[3]] 再压得 [1,2,3]。两条路一样。对。

List 单子的实际意义：bind 就是"对每个结果再生出一串结果，然后全部拼起来"。它天然表达"不确定数量"——一个输入可能对应零个、一个或多个输出。

1.5 例子二：State（带状态的算）

固定一个状态类型 S，令 TA = S → (A × S)。

  • Tf：给 f : A → B，Tf(g) = λs. let (a, s') = g(s) in (f(a), s')。
  • η_A(a) = λs. (a, s)，不动状态。
  • μ_A：给 g : S → ((A × S) × S)（两层），压平 μ_A(g) = λs. let ((a, s1), s2) = g(s) in (a, s2)。

注意 μ 取的是外层的状态 s2，不是内层的 s1。这一点是 State 单子的全部要害：后发生的状态覆盖先发生的。写反了就变成"状态永远是最初那个"，三条律里结合律会立刻炸。

验结合律（这是今天必须手算的一条）：三层状态 h : S → (((A × S) × S) × S)。

  • 先压外面：μ(μ(h))(s) —— 先 μ(h) 得到两层，再压。
  • 先压里面：μ(Tμ(h))(s)。

两条路都得到"取最外层最后那个状态"。具体算：设 h(s) = (((a, s1), s2), s3)。

  • μ(h)(s) = ((a, s1), s3)（内两层压平，取 s3）。再 μ 得 (a, s3)。
  • Tμ(h)(s) = ((a, s2), s3)（把内层先压成 (a, s1) 再包？这里要小心，我算错过一次，见 TDD 第一题）。最终再 μ 得 (a, s3)。

两条路都是 (a, s3)。一致。

1.6 反例：一个"看起来是单子"的构造

取 TA = A × A（把值复制一份）。

  • η_A(a) = (a, a)。
  • μ_A((a,b),(c,d)) = (a, d)，取第一个的第一个、第二个的第二个。

左单位：μ(Tη(a,b)) = μ((a,a),(b,b)) = (a,b)。对。 右单位：μ(η(a,b)) = μ((a,b),(a,b)) = (a,b)。对。 结合律：三层 (((a,b),(c,d)),((e,f),(g,h)))。

  • 先压里面：μ 作用在内层对 ((a,b),(c,d)) 得 (a,d)，外层是 ((a,d),(e,h))，再压得 (a,h)。
  • 先压外面：外层对 (((a,b),(c,d)),((e,f),(g,h))) 直接压得 ((a,b),(g,h))？这里要按 μ 的定义逐层来——外层结构是 (X, Y) 其中 X = ((a,b),(c,d))、Y = ((e,f),(g,h))，μ 取 X 的第一个第一个 a 和 Y 的第二个第二个 h，得 (a,h)。

两条路都是 (a,h)。这个构造居然过了三条律。

但它不是"复制单子"，因为它的 η 和 μ 不自然——μ_A 依赖分量位置（第一个、第二个），换一个对象或换一个箭头，这个"位置"就没有统一含义。这正好说明：三条律只是必要条件，不是充分条件；还要要求 η、μ 是自然变换。自然性这一条在编程里经常被忽略，因为程序员只在自己的类型上验，不验"对所有对象同时成立"。

1.7 单子与伴随的关系

每个单子都来自一个伴随对：若 F ⊣ G，F : C → D、G : D → C，则 T = G ∘ F 是 C 上的自函子，η : Id ⇒ GF 是伴随的单位，μ = G ε F 是伴随的余单位夹出来的。

反过来，每个单子都能分解成伴随——而且分解不唯一。两种标准分解：

  • Kleisli 分解：对象还是 C 的对象，箭头 A → B 换成 A → TB。
  • Eilenberg–Moore 分解：对象换成"T-代数"，即 (A, a : TA → A) 且满足 a ∘ η_A = id_A、a ∘ μ_A = a ∘ Ta。

Kleisli 是"最小的那个"，EM 是"最大的那个"。同一个单子，两头分解出来的范畴不一样，中间的箭头也不一样——但复合回去都是同一个 T。

这一条我第一遍没看懂，以为"分解不唯一"意味着"单子不是本质"。后来想明白：分解不唯一恰恰说明单子比伴随更粗——它把"怎么分解"这个信息丢掉了，只留下"包起来再压平"这个操作。单子是伴随的商。

1.8 接口总表

| 概念 | 类型 | 用一句话说 | |---|---|---| | 自函子 T | C → C | 包一层 | | η | Id ⇒ T | 裸值进包 | | μ | T² ⇒ T | 两层压一层 | | bind | TA × (A → TB) → TB | 包着的东西接着算 | | Kleisli 范畴 | 箭头 A → TB | 拿单子当"广义函数"的范畴 | | EM 代数 | (A, TA → A) | 单子的"模型" | | 三条律 | 左单位、右单位、结合 | 压平必须无歧义 |

二、TDD：三道题

2.1 题一：用 bind 定义的单子，三条律怎么对上

题目：给定 T、η、bind，其中 bind : TA × (A → TB) → TB，且假设 bind(m, η) = m、bind(η(a), f) = f(a)、bind(bind(m, f), g) = bind(m, λa. bind(f(a), g))。要求：把 μ 定义成 μ_A(x) = bind(x, id_{TA})，证明 μ 满足三条律。

我先猜的解法：直接把 μ 代进去，逐条展开，三条律应该都是 bind 公理的直接改写，一行一条。

错在哪：第一条左单位就卡住了。我要证 μ_A ∘ T η_A = id，代进去得 bind(Tη_A(x), id) = x。可我知道的公理是 bind(η(a), f) = f(a)，左边是 Tη_A(x)，不是 η(某物)。我把 Tη 当成了 η，混了一层——Tη_A : TA → TTA 是把整个 TA 包起来，η_{TA} 才是这个动作；而 Tη_A 是"对 TA 里每个元素做 η"，两个箭头在列表单子上恰好长得像（都是"每个元素包一层"），但在 State 单子上完全不是一回事。

这就是今天第一次踩的坑：Tη 和 η_T 长得像，但方向不同、含义不同。Tη_A : TA → TTA 与 η_{TA} : TA → TTA，两个箭头同一个源同一个靶，但不是同一个自然变换的分量。在 bind 语言里，Tη_A(x) 对应"对 x 里的每个结果做 return"，η_{TA}(x) 对应"把整个 x 当成一个结果 return"。

正确的路径：

先算 Tη_A 在 bind 语言里是什么。对 x : TA，Tη_A(x) 是把 x 的每个结果 a 换成 η(a)——也就是 bind(x, η)。那么 μ_A(Tη_A(x)) = bind(bind(x, η), id)，用结合律 = bind(x, λa. bind(η(a), id))，用左单位 = bind(x, λa. id(a)) = bind(x, id) = μ_A(x)……这证出的是 μ ∘ Tη = μ，不是 μ ∘ Tη = id。

又错了一次。问题在最后一步：我要证的是 μ_A ∘ Tη_A = id_{TA}，而上面算出 μ_A ∘ Tη_A = μ_A，除非 μ_A = id，否则不成立。这说明我的 Tη_A = bind(x, η) 这一步就是错的。

重新看：Tη_A 的定义是 T 作用在箭头 η_A : A → TA 上，得到 Tη_A : TA → TTA。它作用在 x : TA 上，得到的是"把 x 的每个结果 a 换成 η_A(a) = [a]"——在 List 上就是 x = [1,2] ↦ [[1],[2]]。这在 bind 语言里确实是 bind(x, λa. η(a)) = bind(x, η)。那么 μ(bind(x, η)) = bind(bind(x, η), id) = bind(x, λa. bind(η(a), id)) = bind(x, λa. a) = bind(x, id) = x。

最后一步 bind(x, id) = x 就是右单位律（把 id 换成 η？不对）。等等：bind(x, id) 里 id : A → A，但 bind 要求第二个参数是 A → TB，id 的类型不对。

第三次错：类型没对齐。bind(m, f) 要求 f : A → TB；我写的 λa. a 是 A → A，不是 A → TA。正确的写法是 λa. η(a)，那又绕回去了。

真正对的做法是把右单位律写成 bind(x, η) = x（这是题设给的第一条公理：bind(m, η) = m）。于是：

μ_A(Tη_A(x)) = bind(bind(x, η), id_{TA})，结合律 = bind(x, λa. bind(η(a), id))，左单位 bind(η(a), id) = id(a) = a，得 bind(x, λa. a)——这里 λa. a : A → A 仍然是类型错的。问题的根源是我把 id_{TA} 当成了 bind 的第二个参数，但 id_{TA} : TA → TA，而 bind(x, ·) 的第二个参数必须是 A → TA。

所以 μ_A(x) = bind(x, id_{TA}) 这个定义本身就写错了：id_{TA} 的类型是 TA → TA，不是 A → TA。正确的是 μ_A(x) = bind(x, η_A)——用 η_A : A → TA 当第二个参数，正好类型对，而且 bind(x, η_A) = x（右单位律），这说明我这个定义又把 μ 定义成了恒等，还是错的。

到这里我意识到用 bind 定义 μ 的正确写法是 μ_A(x) = bind(x, id) 在"bind 的参数是 A → TA"这个约定下根本写不出来——因为 μ 的作用是把 TTA 压成 TA，它的输入是 TTA，而在 bind 语言里 TTA 的元素是 TA 的元素，所以 μ_A = bind(·, id_{TA}) 里的 id_{TA} 恰好是 TA → TA，与 bind 要求的 TA → T(TA) = TTA 不符。

真正的对应是：μ_A = bind_{TA}(·, id_{TA}) 里的 bind 是在 TA 这个对象上的 bind，它的第二个参数类型是 TA → T(TA)…… 也还是不对。

我在这里停了大概二十分钟，然后换了一条路：不去强行用 bind 定义 μ，而是接受 μ 是原始的，反过来用 μ 定义 bind：bind(m, f) = μ_B(Tf(m))。然后三条律全部变成 μ、η、T 的自然性练习。这条路一次就通了。

那条可复用的判据：当你发现"用 A 定义 B"来回出错时，先看两边的类型对不对得上；类型对不上不是笔误，是这条路本身不通。类型是免费的证明检查器，我这一题错了三次，三次都是类型错，却每次都以为是代数算错。

2.2 题二：每个单子都来自一个伴随

题目：给定单子 (T, η, μ)，构造 Kleisli 范畴 C_T，并说明 T 是某个伴随对的复合。

我先猜的解法：对象还是 C 的对象，箭头 A → B 定义成 A → TB，复合用 bind，然后宣称 F ⊣ G 显然成立。

错在哪：我把"构造出一个范畴"当成了"构造出一个伴随"。这两件事差得很远——要证伴随，得写出 F、G 两个函子，还要写出单位和余单位，还要验三角恒等式。我上一题刚在"类型对不对"上栽过，这一题又想跳过验算。

正确的路径：

1. 定义 C_T：对象 Ob(C_T) = Ob(C)；箭头 C_T(A,B) = C(A, TB)；恒等箭头 id_A = η_A : A → TA；复合 g ∘_T f = μ_C(Tg(f))，其中 f : A → TB、g : B → TC。 2. 验范畴公理：结合律由 μ 的结合律给出；单位律由左右单位律给出。这一步不能省，而且要用到"μ 自然"和"T 是函子"两条。 3. 定义 F : C → C_T：对象不动；箭头 f : A → B 映成 η_B ∘ f : A → TB。 4. 定义 G : C_T → C：对象 A ↦ TA；箭头 f : A → TB 映成 μ_B ∘ Tf : TA → TB。 5. 验 F ⊣ G：单位 η 就是 Id ⇒ GF（因为 GF(A) = TA）；余单位 ε : FG ⇒ Id_{C_T}，其中 FG(A) = TA（作为 C_T 的对象，还是 A），而 ε_A : A → TA 在 C_T 里就是 η_A……这里我又卡了一次，因为 C_T 的箭头就是"到 T 里的箭头"，FG 在对象上不动，所以余单位只能是 η 本身，三角恒等式退化成单子的两条单位律。

这一题最后没有证完——我证到"复合的结合律来自 μ 的结合律"就停了，三角恒等式那一步只写了"由左右单位律给出"，没有逐项展开。按昨天的标准，这是一处省掉的"显然"。我把它记在错题本里，不假装证完了。

代价：这一题花了我将近一小时，产出只有半页。但这半页让我第一次看清"单子 = 伴随的商"这句话到底在说什么：C_T 的箭头比 C 的箭头多了一层 T，F 把普通箭头塞进 T，G 把 T 里的箭头压回来，两头夹出来的 GF 就是 T。

2.3 题三：State 单子的结合律，逐点算一遍

题目：取 TA = S → A × S，η_A(a) = λs. (a, s)，μ_A(h) = λs. let ((a, s1), s2) = h(s) in (a, s2)。要求：证 μ ∘ μ_T = μ ∘ T μ，并且指出两条路各自"取的是哪个状态"。

我先猜的解法：状态单子的结合律"就是最后的那个状态赢"，没什么可证的。

错在哪：这句话是对的，但它是一句结论，不是证明。而且我第一遍写 T μ 的时候写成了"对结果做 μ"——实际上 T μ 是 T 作用在自然变换 μ 上，得到的是"在状态单子内部把内层压平"，它的定义 (T μ)_A = T(μ_A)，也就是 λh. λs. let (x, s') = h(s) in μ(x) ... 这种形状。写错这一层，后面两边的式子对不上，我还以为是"取错状态"。

正确的路径：设 h : S → ((A × S) × S) × S，记 h(s) = (((a, s1), s2), s3)。

左边 (μ ∘ μ_T)(h)(s)：先 μ_T(h) : S → (A × S) × S，它把最内两层压平，得 μ_T(h)(s) = ((a, s1), s3)（因为 μ 的定义取外层状态 s3）。再 μ 作用，得 (a, s3)。

右边 (μ ∘ Tμ)(h)(s)：先 Tμ(h)，把内层两层压平，得 Tμ(h)(s) = ((a, s2), s3)。再 μ 作用，得 (a, s3)。

两边都是 (a, s3)。而 s1、s2 都被丢掉了——这就是"后发生的状态覆盖先发生的"。

再做一遍别的取法，验证它为什么必须是 s3：如果把 μ 写成 λs. let ((a, s1), s2) = h(s) in (a, s1)（取内层状态），那么左边得 (a, s1)、右边得 (a, s2)，两条路不同，结合律炸。所以"取外层"不是风格问题，是唯一的正确选择。这一条我原先以为是"实现细节"，其实它就是结合律逼出来的。

那条可复用的判据：当你写一个"压平"操作时，问一句"两层里我保留了哪一个"；如果两条压平路径会保留不同的那个，这个压平就不满足结合律。结合律不是在验算，它是在告诉你该保留谁。

三、手算三例

3.1 Maybe（可能失败）

TA = A + 1（要么有值，要么空）。η(a) = Just a。μ(Just (Just a)) = Just a、μ(Just Nothing) = Nothing、μ(Nothing) = Nothing。

三条律：左单位 μ(Just (Just a)) = Just a；右单位 μ(Just (Just a)) 也是 Just a，而 μ(Nothing) 两侧都是 Nothing；结合律四种情形逐一验，全过。

这个单子最有用的一句：bind 遇到 Nothing 自动短路，不用写 if。它把"失败"这个控制流编进了类型里。

3.2 Reader（读环境）

TA = E → A（固定环境类型 E）。η(a) = λe. a。μ(g) = λe. g(e)(e)——注意 g(e) 是一个 E → A，要再用同一个 e 喂一次。这里如果把第二个 e 写成一个新的环境参数，结合律立刻不成立。

Reader 的 μ 是"同一个环境喂两次"，这和 State 的"取最外层状态"是同一种思路：上下文只能有一种传递方式，不能有两套。

3.3 Writer（记日志，固定一个幺半群 M）

TA = A × M。η(a) = (a, e)（e 是 M 的单位）。μ((a, m1), m2) = (a, m1 · m2)。

三条律等价于 M 的单位律与结合律——这是今天最漂亮的一处：Writer 单子的三条律不是自己证的，是从 M 的幺半群公理抄过来的。这也解释了为什么 Writer 要求 M 是幺半群而不是随便一个类型。

手算：μ(η((a,m))) = μ((a,e),m) = (a, e·m) = (a,m)，右单位靠 e·m = m。结合律靠 (m1·m2)·m3 = m1·(m2·m3)。全对。

这一例让我第一次感觉到"单子律不是新东西，是把已有结构的公理搬过来"。List 靠的是"拼接"这个幺半群，Writer 靠的是显式的 M，State 靠的是"函数复合"这个更隐蔽的幺半群。三个例子，三种搬法，同一个形状。

四、十二条坑

前五天每次都在"连接词"上出错，今天换了个形状：错在类型和层级上。十二条，每条后面跟一个可以当场做的动作。

坑一：把 Tη 当成 η_T。 两个箭头源和靶都一样（TA → TTA），但一个是"把 TA 里每个结果包起来"，一个是"把整个 TA 当成一个结果包起来"。在 List 上它们碰巧长得像，在 State 上完全不同。动作：写下箭头时，在 T 和 η 中间画一个点，标明谁是函子、谁是自然变换，别让它们粘在一起。

坑二：用 bind 定义 μ 时忘了类型。 bind(m, f) 要求 f : A → TB，而 μ 需要的参数是 TA → TA 这一侧的箭头，两边类型对不上。动作：写 bind 之前先把三个类型写出来（m 的类型、f 的类型、返回类型），对不上就说明这条路不通，别硬改。

坑三：把结合律当"压平当然一样"。 结合律是一条硬要求，它排除掉很多"看起来能压平"的构造（比如把 TA = A × A 的 μ 取成"取第一个的第一个、第二个的第二个"，三条律过了，但 μ 不自然）。动作：每写一个 μ，先问"这个选择依赖不依赖分量的位置"，依赖就说明它不自然。

坑四：自然性只在自己的类型上验。 程序员只验 T 在自己那几个类型上的行为，不验"对所有对象同时成立"。单子要求 η、μ 是自然变换，也就是对所有 f : A → B 都要 commutate。动作：随手挑一个"不像自己领域的"对象（比如把 A 换成 1、换成 ∅），看方块还交不交换。

坑五：μ 取错状态。 State 的 μ 必须取外层状态；取内层，结合律立刻炸。动作：手算一个三层的例子，两条路各算一次，看第二个状态有没有被丢掉。

坑六：把"每个单子都来自伴随"当成"分解唯一"。 分解不唯一（Kleisli 最小、EM 最大），所以单子比伴随粗，它是伴随的商。动作：说"来自伴随"时，接一句"哪一种分解"，不说就是含糊。

坑七：把 Kleisli 箭头当成普通箭头。 C_T(A,B) = C(A,TB)，复合不是普通复合，是 μ 夹出来的。动作：写复合时把 μ 显式写出来，别省略。

坑八：以为 bind 比 μ 更"本质"。 两者等价，但证明方向不同：用 bind 证容易把结合律当独立公理（其实它是 μ 的自然性 + 结合律）；用 μ 证能看见"三条路必须一样"这个几何事实。动作：先用 μ 证一遍，再用 bind 改写，看哪一步在 bind 语言里消失了。

坑九：把 List 的 μ 当成"拼接就行"。 拼接是幺半群运算，顺序不能换；如果写成"排序后拼接"，三条律里结合律还在，但和 Tf 的自然性会打架（排序破坏了 map 的顺序）。动作：验"自然性"时用一个不保序的函数当 f，看会不会炸。

坑十：State 的 η 写成"重置状态"。 η_A(a) = λs. (a, s)，不能写成 λs. (a, s0)（用初值）。写成后者，左单位律在"状态已经被改过"的情形下立刻失败。动作：用一个"先改状态再 η"的例子验左单位。

坑十一：Writer 的 M 随便给个类型。 必须是幺半群，要有单位和结合。给个只有半群结构的（比如正整数加法，没有零），η 就写不出来。动作：先写下 M 的单位元和结合律，再写 η、μ。

坑十二：把单子当"容器"。 单子不是容器，是"上下文 + 压平规则"。容器（List、Maybe）只是恰好长得像容器；State 和 Reader 没有容器的样子，它们包的是"一个还没喂进去的输入"。动作：遇到"这东西怎么装进去"的问题，改问"这个东西的上下文是什么、两层怎么压成一层"，问题通常自己就散了。

五、八条判据

P1：能写出 T、η、μ 三个东西的类型。 写不出类型，说明还在用比喻。这一条能筛掉九成的"我觉得我懂了"。

P2：能举两个例子、一个反例。 例子要来自不同领域（一个"容器型"、一个"函数型"），反例要能过三条律但不过自然性，或者反过来——说不清反例坏在哪，等于没有反例。

P3：能手算一条三层结合律。 不是"显然成立"，是把两条路各算一次，指出中间哪些量被丢掉了。

P4：能说清 bind 和 μ 的翻译。 bind(m,f) = μ(Tf(m))，并且能指出这个式子里哪个箭头是 T 的作用、哪个是 μ 的作用。

P5：能说出这个单子的"上下文"是什么、为什么必须这样压平。 State 的答案是"状态只能有一个流向，后覆盖前"；Writer 的答案是"日志必须按发生顺序拼"；Maybe 的答案是"失败要短路"。说不出"为什么必须这样"，说明只是背了定义。

P6：能说出它来自哪个伴随。 哪怕只说得出 Kleisli 那一侧，也算过。

P7：能指出一个"看起来是单子但不是"的构造，并说清它坏在哪一条。

P8：能把它接到自己手上的东西上。 今天接了三处（见第九节），接不上说明还没学会用。

6.2 两处"在描述自己"

第一处：写 2.1 的时候，我写了一句"我在这里停了大概二十分钟，然后换了一条路"。这句话本身没问题，是记录。但我接着写了"这条路一次就通了"——这句是在夸自己，不是在记事实。事实是：换路之后我又错了两次（Tη 与 η_T 混、bind 的参数类型），只是错得更快。把"错得更快"写成"一次就通"，是在替自己修一条好看的曲线。

第二处：第五节判据 P8 里我写"今天接了三处，接不上说明还没学会用"。这句话的主语是"你"，看起来像在给别人写判据，但它其实是我在给自己找一个体面的台阶——万一接不上，就可以说"那说明还没学会，很正常"。判据应该是硬邦邦的："接不上就是没学会"，不带安慰。

两处都是同一个动作：在事实外面裹一层对自己的照顾。这个动作很轻，轻到写的时候不觉得，回头看才看得出来。

6.3 边界

边界一：T 必须是自函子，所以只能在同一个范畴里绕。 如果想"跨范畴"地包（比如从集合到拓扑空间），单子就不够用了，要用相对单子或者伴随。我这次没有碰跨范畴的情形，所以"单子能表达一切上下文"这句话在我这里是没有被检验过的。

边界二：三条律只管"压平无歧义"，不管"这个上下文有没有意义"。 任何自函子配上合适的 η、μ 都能成单子（甚至恒等函子配上恒等自然变换就是一个平凡单子）。所以"这是个单子"这句话的信息量比听起来小得多。真正有信息的是"为什么这个上下文必须这样压平"。

边界三：bind 的控制流是"顺序"的。 单子表达的是"先算这个，再拿结果算那个"，它表达不了"同时算两个再合并"——那是应用函子（applicative）的事，比单子弱。反过来说，所有单子都是应用函子，反之不成立。这条边界我今天是第一次真正理解：单子强在"后一步依赖前一步的结果"，也弱在"必须顺序"。

边界四：我证不出"单子就是计算"这种大话。 今天所有内容都在"给定一个单子，它满足什么"这一侧；"为什么编程里的副作用要用单子建模"这一侧，我只知道结论（Moggi 1991），没有读过原文，不知道他当时要解决什么问题、为什么选这个形状。这一块我标"只有名字"。

七、错题本

今天记三条，都是同一个病：在该问"这一步凭什么"的地方，拿一个更小的东西顶上。

第一条顶上的是"符号"。题一我三次写错类型，每次都以为是自己抄错了箭头，于是改符号而不改路线。符号是最小的东西：改它不需要承认路线错了。但类型错误不是符号问题，它是路线问题——同一个位置上写什么都对不上，说明这个位置在整条路上就不该存在。

第二条顶上的是"显然"。题二的三角恒等式，我用"由左右单位律给出"六个字换掉了三行验算。这六个字不假，但它把"我需要写三行"这件事藏起来了。藏起来之后，下一篇笔记里我就会以为这条我证过。这是最坏的一种：它不会让我当场出错，只会让我以后错得更自信。

第三条顶上的是"反例的壳"。我在 1.6 写了一个 TA = A × A 的构造，三条律全过，然后我判它"不是单子，因为 μ 不自然"。这个判断是对的，但写的时候我发现自己在偷懒：我只说了"不自然"，没有真的找出一个 f 让方块不交换。反例如果没有具体箭头，它就只是一个壳，壳是不能当证据用的。

三条加起来，是我这五天里最稳定的一种错法，只是每天顶替的东西不同：11-21 顶替的是结论（用待证的结论证自己）、11-22 顶替的是"显然"、11-23 顶替的是"近似当精确"、今天顶替的是符号和反例的壳。四种顶替物，一个动作：在该付代价的地方，付得更少。

这条我暂时没有解法，只有一个检查动作：每次写下"显然""由……给出""不自然"这几个词，就在旁边画一个小方框，逼自己填一行具体的东西进去。填不出来，就把这三个词删掉，改成"这里我没算"。

八、五处对照：把手上的东西往单子上靠

这一节是今天最花时间的部分，也是唯一可能"真的用上"的部分。我把手上五样东西逐一试着往单子上靠，靠得上的写清楚靠在哪，靠不上的写清楚为什么。

8.1 continuity 的三本账：不是单子，是三个独立的账

我第一反应是"三本账（锁、工件、交接）合成一个状态，那就是 State 单子"。写到一半发现不对：三本账之间没有压平关系。锁的记录不会被工件的记录压平，工件也不会被交接压平。它们是并排放着的三个文件，各自追加，互不消化。

单子的 μ 要求"两层压成一层"，而三本账是"三份并排"，这更像余积（三个不交的标签），而不是单子。这个判断昨天（余极限那课）已经做过一次，今天再验一遍，结论一样：它是有三个内射的余积，不是被压平的 TTA。

真正的对照点在这里：如果哪天要给账本加"跨会话合并"（把两个会话的锁合成一条），那时候才可能出现一个压平操作，才可能问"这个压平满足结合律吗"。现在问早了。

8.2 imperfect 的衰减：连函子都不是

imperfect 的状态是四个维度按半衰期往基线衰减，再加一点抖动。我原想写"这是一个 State 单子：状态 s 加上一个推进函数"。

写下去第二行就卡住：State 单子的 T 必须是函子，Tf 要把"结果"部分用 f 作用。而 imperfect 的状态推进不产生结果——它只是把 s 变成 s'，没有任何 A。硬要套，只能取 A = ()（单位类型），这时候 TA = S → () × S，本质上就是 S → S，一个自映射。

自映射不是函子（它是某个具体范畴里的一个箭头，不是范畴之间的映射）。所以严格的结论是：imperfect 的衰减是一个自映射的迭代，不是单子。它能被"包"进 State 单子（A 取任何东西都行），但它自己不长成单子。

这条对照最大的用处是让我看清一件事："可以用单子来建模"和"这个东西是单子"是两句话。前者几乎对什么都成立（把状态塞进 State 就行），后者要求它自己带一个压平规则。我以前一直混着用。

8.3 rabot 的挑刺：这是一个"选择"，不是单子

rabot 每次从语料里挑一条"离我最近又没读过"的。这个动作里有一个隐式状态（读过哪些），也有一个隐式效果（挑出来之后状态变了）。照 8.2 的逻辑，它可以被 State 包起来。

但它真正有意思的地方不在这里。它有一个"优先级"：有数字的加分、反常识的加分、太厚的扣分。这个优先级是可加的分数，而分数之间没有压平关系——加完就是加完，不存在"两层分数压成一层"。所以它更接近 Writer 单子（累加一个幺半群元素）而不是 State。

而"分数必须可加"这一条，正好是 Writer 的 M 必须满足幺半群律的实例：如果分数不可加（比如用"取最大值"），那 M 就是一个带 max 的幺半群（max 有单位元 -∞），还是能用；但如果用"排名"（1、2、3 名），那就不是幺半群了（两个名次"相乘"没有定义），Writer 立刻失效。

这一处让我第一次觉得 Writer 有用：它在逼你检查"你的累加操作到底有没有单位元和结合律"。rabot 的分数有（0 和加法），名次没有。

8.4 交易判据的合成：这是 Kleisli 复合

三条判据（波动缩放、突破加量、均线过滤）各自给出"做/不做"，合起来给出一个动作。昨天我把它判成"余等化子"（一致域照做、分歧处空仓）。

今天补一个角度：从"单条判据"到"动作"这个过程，本身是一个 Kleisli 箭头。每条判据是 市场状态 → T(动作)，其中 T 是"不确定性"这个上下文（可能空仓、可能部分仓位）。多条判据串起来，就是 Kleisli 复合 μ(Tg ∘ f)——先算第一条的 T(动作)，再拿这个去算第二条。

这个对照的价值在于：Kleisli 复合要求结合律，也就是"先合前两条再合第三条"和"先合后两条再合第一条"必须一样。而现在的实现是 if-else 优先级，优先级不满足结合律——(A 优先 B) 优先 C 和 A 优先 (B 优先 C) 结果不同。这就是为什么昨天的判据说"要改成余等化子"：不是因为余等化子更漂亮，是因为只有满足结合律的合成才是可组合的。

这一处是今天唯一"算出来能改代码"的地方。我记下来，明天回测时一并验。

8.5 调研总纲：它是 Eilenberg–Moore 代数，不是单子

调研总纲（21 份报告的总纲）把 21 个"局部视角"压成一个统一视角。这个动作很像 μ：TTA → TA。

但严格看，它不是 μ，因为 21 份报告不是一个自函子的两次作用，它们只是"一组平行的东西"。把一组平行的东西压成一个，是余极限（昨天的结论），不是 μ（μ 压的是同一个函子的两层）。

不过这里有一个真能对上的东西：总纲一旦写出来，就变成"任何一份新报告都要能嵌进它"——这个"嵌入"关系，正好是 EM 代数的结构映射 a : TA → A：TA 是"被包了一层的新报告"，A 是总纲，a 是"这份报告在总纲里的位置"。而 EM 代数的两条律（a ∘ η = id、a ∘ μ = a ∘ Ta）翻译成人话就是："单份报告直接读总纲"和"先把几份报告合成再读总纲"必须一致。

这条对照今天第一次让我觉得 EM 代数不是摆设：它说的正是"一个框架能不能吃下新东西"这件事。

如果对面坐着一个只学过一点集合论、没碰过范畴的人，我该怎么把单子讲明白。我试了两遍，第一遍失败了，第二遍勉强成功。

第一遍失败在哪里。 我开口就说"单子是一个自函子加上两个自然变换"。对面的人立刻问："自函子是什么？" 我说"范畴到自身的函子"。他问"范畴是什么"。我说"对象和态射"。他问"那我为什么要关心态射"。到这里我就答不上来了——不是因为我不知道答案，是因为我选错了入口。用定义当入口，等于要求对方先接受一整套我还没证明有用的语言。

第二遍换了入口，从"麻烦"开始。 我问：你有没有写过这种代码——一个函数可能失败，失败之后后面的步骤全部要跳过。他说有。我说，最笨的写法是每一步都判断"上一步是不是失败了"，于是每一行都多一个 if。这种写法的问题是：三行代码里有两行在重复同一个判断，而且只要漏一处就出 bug。

然后我说：有一种办法是让"可能失败"这件事自己往下传。你把"一个可能失败的值"当成一种新东西（而不是一个值加一个布尔标记），再规定"这种新东西怎么接下去"——接的规则是"上一步失败就直接失败，不执行下一步"。这条规则只要写一次，后面所有步骤都自动继承。

到这里他会点头。这时候我才说：这个"新东西"就是 T A（T 表示"可能失败"这层壳），"接下去"这个动作就是 bind，而它背后要求的三条律，说的是一件很朴素的事——不管你怎么分组，结果都得一样。

三条律在讲台上怎么翻译。 我是这么说的：

左单位律讲的是"第一步之前什么都没发生"。如果你把一个纯值包起来（η），立刻接一个函数，那结果应该等于直接对那个纯值调用这个函数。换句话说，包一下再接，等于不包直接接。如果这条不成立，说明"包"这个动作本身带副作用，那它就不该叫"包"。

右单位律讲的是"最后一步不改变任何东西"。如果你算完一步，最后接一个"把结果原样包起来"的动作，那结果应该等于没接。这条不成立的话，你就不能在任何地方安全地收尾。

结合律讲的是"先做前两步"和"先做后两步"必须一样。这条最实在：它保证你可以把一段流程抽成一个函数而不改变语义。如果结合律不成立，那你每次重构都在偷偷改行为——这正是很多"看起来只是抽了个函数，结果线上炸了"的来源。

一个必答的问题：那它跟"异常处理"有什么区别。 我给的答案是：异常处理是"往外抛"，单子是"往里包"。抛出之后，控制流跳到了别处，你没法在类型上看见它；包起来之后，"可能失败"写在类型里（T A 而不是 A），编译器能替你检查每一步有没有处理它。这是同一件事的两种态度：一个把麻烦甩给运行时，一个把麻烦写进类型。

第二个必答的问题：为什么要有两个变换（η 和 μ），一个不够吗。 我用"套娃"讲：T A 是一层壳，T (T A) 就是两层壳。你从纯值出发，包一次得到一层（这是 η）；你把一个"已经算过一段的结果"再拿去接下一步，就会自然产生两层壳，必须有人把它压回一层（这是 μ）。如果只有 η 没有 μ，那么每接一步就多一层壳，三层之后类型变成 T (T (T A))，你就得为每一层写一个压平函数——这就是我说的"笨写法"。μ 存在的全部意义是：不管多少层，一次压平。而结合律保证"一次压平"和"分几次压平"结果相同。

讲完这两段，他说了一句让我意外的话："那这不就是把 try/catch 变成一种类型吗。" 我说对，但多了一样东西：它还能表达"日志""状态""环境"这些跟失败无关的东西，因为它们共享同一个形状——"一层壳 + 一个压平规则"。

讲到这里我停了。 我没讲伴随、没讲 Kleisli、没讲 EM 代数。原因是：讲到这一步，他已经能自己写一个 Maybe 单子并且解释为什么三条律必须成立；再往下讲分解，只会让他以为"单子的重点是那些高级构造"，而重点其实是那个形状。教学里最贵的判断是"到哪里停"，这一条我今天才真正做了一次，而不是嘴上说说。

十、单子为什么不是基础

这一节是给自己纠偏的。我这几天的直觉一直是"单子是底层结构"，因为编程里所有副作用都能用它表示。今天读完自己的笔记，我改主意了：单子不是基础，伴随才是。

理由是三条。

第一，单子是从伴随里掉出来的，不是反过来。 任何一个伴随 F ⊣ G 都给出一个单子 T = G ∘ F，η 是伴随的单位，μ = G ε F 是伴随的余单位被夹出来的。这个构造不需要额外假设。反过来，给你一个单子，你能造出伴随（Kleisli 或 EM），但造法不唯一——也就是说单子丢掉了信息。凡是有损的构造，都不该叫基础。

第二，单子的三条律是"压平无歧义"，不是"存在"。 恒等函子配上恒等自然变换就是一个单子，它什么也没说。这说明"是单子"这个性质的约束很弱：它约束的是压平的方式，不约束被压平的东西是什么。真正的信息在"这个单子是从哪个伴随来的""为什么必须这样压平"。

第三，从使用角度看，单子好用恰恰因为它是"商"。 Kleisli 范畴把伴随的两边粘成一边，让你不必每次都写 F 和 G；EM 范畴把代数结构显式化，让你能谈"这个框架吃不吃得下新东西"。两者都是把伴随的某个侧面投影出来。用投影当基础，会在需要另一个侧面的时候立刻不够用——这就是为什么"单子解释不了一切"。

那"基础"应该是什么？我现在的答案是：基础是"一个东西可以用两种方式看，而且两种看法的转换本身有结构"——这就是伴随。泛性质说"由关系定义"，伴随说"两个方向互为最优"，单子说"其中一个方向被粘起来了"。三级递进，越往下越具体，也越丢信息。

这一条对写作有直接影响：以后我要讲清一个结构，应该先讲它从哪个伴随来，再讲它粘成了什么形状。反过来讲（先讲形状再补来处），听的人会觉得"这套东西是凭空规定的"，而实际上它每一步都有不得不这样的理由。

十一、变体与推广：单子周围的一圈东西

今天只在单子这一个点上挖，但挖到一定深度就会撞见它周围的邻居。我把撞见的六个记下来，每个只写"它跟单子的差别在哪"，不展开（展开就是第二个对象了，违反"一天一个"）。

应用函子（applicative）。 它比单子弱：有 η，有一个"把包着的函数作用到包着的值上"的操作（<*>），但没有 μ。差别在能力上：应用函子能表达"同时算两个再合并"，不能表达"后一步依赖前一步的结果"。举例：解析两个独立的配置项可以，解析"先读数量、再按数量读那么多行"不行——后者需要单子。这条差别今天第一次变得具体：单子强在依赖，弱在必须顺序。

箭头（arrow）。 它是应用函子和单子之间的一档，能表达"依赖"但把"输入输出"显式化。它比单子多出来的东西是：你能在没有 ArrowApply 的情况下谈"这条路线的静态结构"，而单子天生是动态的（每一步的结果决定下一步）。这一条我只知道形状，没用过，标"只有名字"。

余单子（comonad）。 把三个箭头的方向全反过来：ε : T A → A、δ : T A → T (T A)。它的直觉是"从一个上下文里取出当前值，以及'把这个上下文往内看一层'"。如果说单子是"把东西包起来"，余单子就是"从包着的环境里取东西"。我手上的对照：阅读一份文档时的"当前段落 + 前后文"很像余单子（当前值是这一段，上下文是前后文，δ 是"把上下文再包一层"）。这条也没验，只是形状像。

相对单子（relative monad）。 单子要求 T 是自函子（C → C），相对单子允许 T : J → C（从一个更小的范畴进去）。这正好是我今天边界一里说的"跨范畴"问题的一个解法。举一个具体的：把"列表"看成从集合到有序集合的构造，T 不是自函子（进去的和出来的不在同一个范畴），但可以写成相对单子。这条是我今天唯一想继续追的，因为手上的"从原始材料到结构化知识"正好是这个形状。

自由单子（free monad）。 它是"把一组操作符号化，先攒着不执行"。T A 是"一棵由操作组成的树，叶子是 A"。它的用处是把"解释"和"构造"分开：先构造出一棵树（这一步是纯的），再用不同的解释器去跑它。对照到我手上：把一次任务写成一份"该做哪些动作"的清单，再交给不同的执行器跑——这个模式我在 dsh-social 里其实已经做了（endpoint 表 + 引擎），只是当时不知道它叫自由单子。这条是今天最有用的一个"原来我有"。

代数（EM 代数）。 8.5 已经写了：a : T A → A 加上两条律。它的用处是谈"一个框架吃不吃得下新东西"。这一条今天已经用上了。

六个邻居，只有两个真正接上了手上的东西（自由单子、EM 代数），两个只对上了形状（余单子、相对单子），两个只知道名字（箭头、应用函子的严格理论）。这个比例比前五天高一点，但也没高到哪去。

十二、四种母型：单子问题的分类

做完三道题我发现，单子的题目虽然多，但形状只有四种。把它们认出来，比记住定义有用。

母型一：给一个构造，验它是单子。 这是最常见的题型。步骤固定三步：写 T 在对象和箭头上的作用、写 η、写 μ；然后验四条（左单位、右单位、结合律、η/μ 的自然性）。关键在第四步——大部分"验单子"的失败都死在自然性上，因为自然性要求"对所有 f 同时成立"，而人只想验自己关心的那几个 f。

母型二：给一个单子，造它的 Kleisli 范畴。 步骤：对象不变、箭头换成 A → T B、复合用 μ 夹、单位用 η。要点是"复合不是普通复合"，写的时候必须把 μ 显式写出来。这类题的陷阱是把 Kleisli 复合当成普通的函数复合，验结合律时就会漏掉 μ 的那一次作用。

母型三：给两个单子，问它们之间有没有态射。 单子态射要求 T → S 并且跟 η、μ 都交换。这类题的难点在"两个条件可能打架"：一个自然的候选变换往往只跟 η 交换，不跟 μ 交换。判据很实用：先验跟 μ 的交换，因为它是更强的那一条。

母型四：问"这个构造为什么不是单子"。 这是最难也最有价值的一类。答案永远是"它坏了哪一条"，而不该是"它看着不像"。今天我的反例（T A = A × A）坏在自然性，这条我一开始只说了"不自然"没给箭头，属于母型四的失败样本。

四种母型对应四种检查动作：母型一查自然性、母型二查 μ 有没有显式出现、母型三先查跟 μ 的交换、母型四必须给具体箭头。这四条明天可以直接当检查单用。

十四、四个"我以为"

每天都有几个"我以为"，今天四个，全部错在边界上。写细一点，因为它们比结论有用。

我以为一：我以为单子的难点在三条律。

开始写之前，我心里想的是"三条律要验，肯定最花时间"。实际做下来，三条律是最容易的部分——它们都是等式，逐点展开、两边算到同一个表达式就完了，中间不需要任何判断。真正花时间的是写 μ 的那一刻：μ 要选一个"压平的方式"，这个方式必须自然（对所有 f 同时成立），而自然性没法靠"算"验出来，只能靠"看出它依赖不依赖分量的位置"。也就是说，单子里唯一需要判断的地方在 μ 的自然性上，其余全是算。

这个发现可以推广：凡是"多条等式"的结构，难的部分通常不在等式，在"要选什么"。群的三条律也一样，难的是"这个运算定义得对不对"，不是三条律本身。

我以为二：我以为 bind 比 μ 更接近编程直觉，所以应该先写 bind。

题一我一开始用 bind 去定义 μ，三次撞类型错误。换向之后（用 μ 定义 bind）一次就通了。事后想清楚原因：bind 的类型是 (T A, A → T B) → T B，它把"结果"和"下一步"当成两个东西；而 μ 的类型是 T (T A) → T A，它只说"两层变一层"。定义 μ 的时候，我只需要知道"层"这个概念；定义 bind 的时候，我需要知道"值"和"函数"两个概念。概念少的那个更容易写对。

这条对我写文档有直接好处：以后解释一个结构，先给"最少的那个定义"，再给"用起来最顺的那个定义"，最后补一句"两者等价"。

我以为三：我以为 State 的 μ 取哪一层都行，只要类型对上。

类型确实都对得上：T (T A) = S → (S → A × S) × S，压平之后 S → A × S，中间那个 S 你有两种取法（取外层传进来的、取内层被包着的）。我第一遍随手取了内层，因为"内层更靠里、看起来更本质"。结果结合律在三层的时候炸了：某一路把中间那个状态丢了，另一路没丢。

原因是状态是有流向的：外层是"当前的"，内层是"上一次留下的"，压平必须让当前的覆盖过去的，否则历史会倒流。这条不是数学技巧，是"状态"这个概念的语义要求。凡是带流向的东西，压平的方向不能随便选。

我以为四：我以为"能接上手上的东西"是一件容易的事。

第八节我原本打算写五处"这就是单子"，结果三处靠不上。靠不上的三处（continuity 的三本账、imperfect 的衰减、调研总纲）各有各的坏法：一个是余积不是压平、一个连函子都不是、一个是 EM 代数不是单子。

这个结果比"五处全接上"有用得多，因为它给了我一条判据：要判断一个东西是不是单子，先问"它有没有两层要压成一层"，再问"这个压平跟它的自然作用交不交换"。两个问题里任何一个答不上来，就不用往下算了。以前我会先问"它像不像容器"，那个问题几乎总是答"有点像"，于是每次都白算半小时。

十六、今天真正学到的一件事

如果要我今天只带走一条，我带走这条：

一个结构的力量，来自它允许你"只写一次"。

单子的三条律之所以重要，不是因为它们难，是因为它们保证"你写一次压平规则，之后所有层都用同一条规则"。如果没有结合律，你每多一层就得重新想一次怎么压，那时候"单子"就退化成一堆特例。

这条可以搬到别的地方：手上的判据库、日记机制、社交平台接入的 endpoint 表，力量都来自"只写一次"。endpoint 表写一次，九家平台共用同一个引擎；判据写一次，回测脚本可以通用；日记机制写一次，每天不用重新想"今天写什么格式"。

反过来，什么东西没有这个性质，它就不该被当成"结构"来攒，只该被当成一次性的动作。我今天写这一篇，如果明天不能拿它去判一个新东西，那它就只是一次表演。

十七、附记一：为什么是单子，而不是别的

十八、附记二：手算补记

二十三、附记七：单子能给我什么，不能给我什么

这一节是"用得上/用不上"的账，写清楚，免得下次又把它当万能钥匙。

能给的，三样。

第一样是"只写一次"的能力。前面已经说了：压平规则写一次，所有层通用。这条对我的直接用处是——以后写"多步流程"的代码（比如取票、用票、刷新），应该先问"这几步的压平规则是什么"，写成一处，而不是每步都写 if (失败) return。

第二样是"顺序依赖"的显式化。bind 的类型逼着你把"后一步依赖前一步"写出来。这看起来是麻烦，实际是好处：凡是"看起来能并行、其实有依赖"的地方，写成单子会立刻暴露（因为类型不对）。我在 dsh-social 里就吃过这个亏——九个平台的 auth 我一开始想"并行准备"，写下去发现 weibo 的 visitor 票要用在 cookie 头上，是依赖的，不是并行的。

第三样是"比较两个上下文"的框架。单子态射让我能问"Maybe 和 Either 之间有没有保结构的映射"，答案是有（Maybe 看成 Either 的特例，None 映到 Left 某个固定值）。这类比较以前我只能靠"感觉像"，现在有一个可验的条件（跟 η、μ 都交换）。

不给的，三样。

第一样是"什么时候该用单子"。单子只告诉你"给定这个上下文，压平怎么做"，不告诉你"这个上下文该不该存在"。imperfect 的八个维度要不要衰减、衰减多快，这些是产品判断，单子一个字都说不上。

第二样是"这个压平对不对"。三条律只保证"无歧义"，不保证"符合语义"。State 取内层状态也满足"某种"结合律（在某些变体里），但它不符合"状态有流向"这个语义。律是必要条件，不是充分条件。

第三样是"跨范畴"。这是今天的边界一，也是我明天想学层的原因。单子的 T 是自函子，一旦你想"从原始材料到结构化知识"这种跨层的构造，它就不够用了。相对单子是一个补丁，但我还没验。

三样能给、三样不给，比例正好一半。这个比例让我对"学一个结构"这件事的预期更准了：任何结构大约只覆盖一半的问题，另一半要靠别的结构或者干脆靠判断。

二十六、附记九：把今天的三条判据写成触发句

判据不写成触发句，就只会留在这一篇里。今天这三条我试着写成"看到 X，先查 Y，因为 Z"的形状。

触发句一：当我看到"两层可以压平"的时候，先查"压平之后哪一层的量还活着"，因为压平必然要丢一层，丢错层不会当场报错，只会在更长的组合里炸。

这条来自 State 取内层那个坑。它的关键在于"压平必然丢东西"这一点——很多人以为压平是把两层合成一层新的，其实大多数时候是把某一层丢掉、保留另一层。丢掉哪一个，是整个构造里最需要判断的地方，也是三条律验不出来的地方（三条律只验同一个 μ 的自洽，不验"该丢哪层"）。

触发句二：当我看到"这条显然成立"的时候，先查"如果要写出这一行，我需要写几个下标"，因为'显然'这个词总是出现在下标最容易混的地方。

这条来自第二遍手算里那个"两条路算出同一表达式"的假成功。更宽一点说，"显然"出现的位置差不多总是"符号重复使用了、所以看不出差别"的位置。写不出下标就是没算。

触发句三：当我看到"等价"两个字的时候，先查"另一个方向算过没有"，因为等价要算两个方向，而人总是只算顺的那个方向。

这条来自 Writer 那四十分钟。顺的方向（单子律 ⟹ 幺半群律）几乎是展开就完；逆的方向（幺半群律 ⟹ 单子律）要构造 μ，要验三条律，是真正的一半。只算顺方向就说完"等价"，是这一行里最标准的偷工。

三条触发句有一个共同点：它们都不说"要注意"，而是说"去查一个具体的东西"（哪层活着、要写几个下标、另一个方向）。能指出"查什么"的判据才有用，"要小心"这种话等于没说。

二十七、附记十：为什么手算比看证明有用

今天有两处是"看证明看不懂，手算才懂"的：State 的结合律、Writer 的逆方向。我把原因想清楚了，写下来。

看证明时，我只能看见"合法的步骤"。 每一步都是对的，所以我不知道"哪里可能错"。手算时我自己会写错，写错的地方恰好是结构最脆的地方——State 那次我把 s2 丢了，那个位置正是"哪一层存活"的判断点；Writer 那次我漏了"μ 要自然"，那个位置正是"构造 μ 时必须选一个规则"的判断点。

看证明时，符号是别人选的。 别人用 s、m、f，不会撞；我自己算的时候图省事复用同一个符号，一复用就出假成功。这说明"符号管理"不是形式主义，它是手算的核心技术：每个不同的东西必须有名字，而且名字要能看出它属于哪一层。

看证明时，我不知道代价。 手算会让我知道"这一步要写三行"，于是我知道这条路贵不贵。今天题二我用"由左右单位律给出"跳过三行，就是因为看证明时那三行看起来"显然"。手算过一次之后，我就知道那三行里有一行要展开 μ 的自然性——它不是显然的。

这条经验可以推广到所有"学结构"的场合：先手算一个最小的例子，再去看一般证明。顺序反了，读证明就只是"确认自己没读错"，学不到东西。
