今天第一课。一天一个对象，从最小的那个开始：集合与函数的范畴。

一、SDD：Set 的接口文档

1.1 对象是什么

我要写的这个对象叫 Set。它不是"集合的集合"，那是个悖论。它是一个范畴，由三样东西组成：一堆对象、一堆态射、一个合成运算。写接口文档的时候，先把这三样的类型写清楚。

  • 对象：任意集合。记作 A、B、C。
  • 态射：给定两个集合 A、B，从 A 到 B 的函数的全体，记作 Set(A, B) 或者 Hom(A, B)。
  • 合成：给定 f : A → B 和 g : B → C，得到 g ∘ f : A → C，定义为 (g ∘ f)(x) = g(f(x))。

三行写完，工程上就该问：这三样满足什么律？不写律的接口文档是不合格的，因为它没说清什么东西可以被替换、什么不能被替换。

1.2 律

律一（结合律）：对 f : A → B、g : B → C、h : C → D，有 h ∘ (g ∘ f) = (h ∘ g) ∘ f。

这条在 Set 里为什么成立？因为两边都是函数，而论两个函数相等就是论它们在每一点上的值相等。取任意 x ∈ A：

左边：h ∘ (g ∘ f) 作用在 x 上，先算 (g ∘ f)(x) = g(f(x))，再算 h(g(f(x)))。

右边：(h ∘ g) ∘ f 作用在 x 上，先算 f(x)，再算 (h ∘ g)(f(x)) = h(g(f(x)))。

两个结果逐字相同，因为函数应用满足"先内后外"这个约定，而括号只是改变了计算的顺序，没有改变计算的嵌套结构。这一点值得停一下：结合律说的不是"结果一样"这么弱，它说的是嵌套结构可以由任意方式重新加括号而不变。所以在工程上，结合律给了编译器重排的自由：三个函数串起来，先合前两个还是先合后两个，结果一样，于是可以按性能选。

律二（单位律）：对每个集合 A，存在 id_A : A → A，使得对任意 f : A → B 有 f ∘ id_A = f，对任意 g : B → A 有 id_A ∘ g = g。

id_A 定义为 id_A(x) = x。验证同样是逐点：f(id_A(x)) = f(x)，id_A(g(y)) = g(y)。

这里有一个容易滑过去的点：单位律其实是两条，一条在左边、一条在右边。在 Set 里它们都成立且用的是同一个 id。但在别的范畴里，左单位与右单位可能是不同的东西，所以接口文档必须分别写。这是"律要写全"的第一个例子。

1.3 两个例子，一个反例

例子一：只有一个元素的集合。 取 1 = {*}。那么 Set(1, A) 与 A 的元素一一对应：每个 a ∈ A 给出唯一一个函数 * ↦ a。所以"集合的元素"这个概念可以由"从 1 出发的态射"重新定义。这一步看起来是多余的绕路，但它是后面 Yoneda 那套东西的种子：元素是态射，不是原始材料。

例子二：空集。 取 0 = ∅。那么 Set(0, A) 恰好有一个元素（空函数），而 Set(A, 0) 当 A 非空时没有元素。这条不对称是后面"初对象"与"终对象"的来源：0 是初对象（从它出发的态射唯一），单元素集是终对象（到它的态射唯一）。在 Set 里初对象与终对象不是同一个东西，这是 Set 的一个特征；在别的范畴里它们可以重合。

反例：把"关系"当成态射。 如果我把态射定义成 A 与 B 之间的任意二元关系，合成取关系的复合，那么结合律仍然成立，单位律用恒等关系也成立。所以这不是反例——它是一个不同的范畴，记作 Rel。真正的反例要更小心：如果我把态射定义成"部分函数"（对某些输入没有定义），那么合成仍然是部分函数，结合律成立，单位律也成立（恒等部分函数处处有定义）。这也不是反例，它是另一个范畴，记作 Pfn。

我一开始想举的反例是"把态射定义成单射"，这个确实坏：两个单射的合成是单射，结合律成立；但如果 A 到 B 没有单射（B 比 A 小），那么 id_A : A → A 是单射，单位律在 A 上有；可如果我要的是"每个对象都有恒等态射"，而对象是空集——空集到空集的函数是单射，还行。真正破的地方在于：单射类态射在合成下封闭，但不是所有范畴都这样；把 Set 换成"所有集合与所有单射"，得到的其实是 Set 的一个子范畴，律全成立，只是态射少了。所以这也只是另一个范畴。

到这里我意识到一件事："反例"这个词在范畴论里不太好用，因为只要你愿意改态射的定义，几乎任何东西都能变成一个范畴。真正有意义的"反例"是：同一个对象集合上，两种态射定义，哪种保留了我想保留的信息。所以下面我换一个更有用的反例。

真正的反例：把态射定义成"函数的名字"。 假设我规定态射是从 A 到 B 的函数的表达式，两个表达式即使算出同一个函数也算不同的态射。那么结合律仍成立（表达式可以复合），单位律需要一个"恒等表达式"，也有。于是这也成了一个范畴——而且是程序员最熟悉的那个：它区分"同一个函数的不同写法"。Set 与它的差别只有一条：Set 里两个态射相等当且仅当它们逐点相等；那个范畴里，相等是语法相等。

这一条差别值得写下来，因为它正是后来"类型论"与"集合论"分家的地方：集合论里函数是外延的（只看值），类型论里函数是内涵的（看构造）。我今天的 SDD 只写了外延那一版。

1.4 与我已会的东西的关系

我原来对"函数"的理解是：一个规则，把输入变成输出。范畴论把它拆成三件事：对象（输入输出的类型）、态射（规则）、合成（规则的串联）。拆开之后，"结合律"不再是显然的，而是一个要求；"恒等"不再是无用的，而是一个必需。这一层拆解的直接好处是：它可以搬到不是集合的东西上。

比如预序集：对象是元素，态射是"≤"的证据，两个元素之间要么有一个态射要么没有。合成就是把 a ≤ b 与 b ≤ c 接成 a ≤ c，而传递性就是结合律，自反性就是单位律。所以"偏序"是范畴的一个特例。这个观察比任何例子都值钱，因为它说明范畴论不是"更抽象的集合论"，而是把"什么能接、接完还是不是同一类东西"这件事单独抽出来。

二、TDD：三道题

题一：为什么"群"可以写成一个范畴

题目：一个群 G，能不能看成一个范畴？如果能，对象有几个。

我先猜的解法：我认为群是一个范畴，对象是群的元素，态射是乘法。理由是"乘法可以复合"。

错在：我把"对象"和"态射"搞反了，而且搞反的方式很典型——我看到乘法可以接起来，就以为接起来的是元素，实际上范畴里的"接"是态射的合成，不是元素的运算。元素的运算要成为合成，前提是元素本身得是箭头，而箭头必须有起点和终点。

正确的构造是：对象只有一个，记作 *；态射是群的元素；g 的起点终点都是 *；合成定义为 g ∘ f = gf（群的乘法，注意顺序）；恒等态射是单位元 e。

验四条：

  • 合成封闭：两个元素乘起来还是元素，落回 Hom(*, *)。
  • 结合律：群的乘法结合，正好对上。
  • 左单位：e g = g。
  • 右单位：g e = g。

四条全成立，所以每个群都是"只有一个对象的范畴"。

这条错误值钱的地方：它教我一个判据——当我想把某个代数结构塞进范畴时，先问"对象是什么"，再问"箭头是什么"；如果两个东西都答不出来，说明这个结构不是范畴，而是范畴里某个对象上的额外结构。 群不是"元素构成的范畴"，群是"一个对象上的自同态集合，且其中每个箭头都可逆"。这两句话差别巨大：前者把群当空间，后者把群当一个点上的对称。

顺着这条，可以得到一串对照，全部成立：

  • 群 = 单对象范畴，所有态射可逆。
  • 幺半群 = 单对象范畴，不要求可逆。
  • 预序 = 每个 Hom 至多一个元素的范畴。
  • 一个集合 = 只有恒等态射的范畴（离散范畴）。

这四条一摆，"群、幺半群、偏序、集合"这四个平时分散的概念，变成了同一件事在不同约束下的样子。这就是范畴论的实际用处：不是变抽象，是把散落的东西摆到同一张表上。

第二层错：我一开始还想"那环呢，环是不是两个对象的范畴"。想了一下，不是。环的加法是一个群（单对象范畴），乘法是另一个幺半群（单对象范畴），两者还满足分配律——分配律不是一个"合成"，它是两个结构之间的相容条件。所以环不是范畴，环是"一个集合上挂了两个单对象范畴的结构，并且它们相容"。这条我标为"想清楚了"，因为它把"什么时候该用范畴、什么时候不该"划出一条线。

题二：自由函子为什么是遗忘函子的左伴随

题目：从集合到群，有一个"自由群"构造 F；从群到集合，有一个"遗忘函子" U。为什么说 F 左伴随于 U？

我先猜的解法：我认为"自由"就是"没有多余关系"，所以自由群就是"由生成元自由生成的群"，而左伴随只是说"F 在左边"。这个理解等于把定义重复了一遍，没有信息。

错在：我把"左"当成一个位置，实际上"左"是一个方向的断言：对每个集合 S 和每个群 G，Hom_Grp(F S, G) 与 Hom_Set(S, U G) 之间存在自然的一一对应。左伴随说的是这条对应关系存在，而且"从左到右"的那个映射是沿着 U 的——也就是：给定一个群同态 F S → G，把它限制到生成元上，就得到一个集合映射 S → U G。反过来，给定一个集合映射 S → U G，因为 F S 是自由生成的，任何在生成元上指定的值都能唯一延拓成群同态。

正确的路径与定理链： 1. 自由群的定义：F S 由 S 生成，且除群的公理外没有额外关系。形式化说法是它满足一条泛性质。 2. 泛性质：对任意群 G 与任意函数 f : S → U G，存在唯一的群同态 f̃ : F S → G 使得 U f̃ ∘ η = f，其中 η : S → U F S 是把元素送进生成元的映射。 3. 这条泛性质本身就是伴随的普遍形式：把"唯一延拓"读成"Hom 集之间的双射"，双射的自然是自动的，因为它对 G 的每个同态都成立且与合成相容。 4. 于是 F ⊣ U，η 是伴随的单位。

这条判据：看到一个"自由构造"，就去找它的"唯一延拓"性质；找到唯一延拓，就等于找到了一个左伴随。 反过来，看到"遗忘"，就想"我丢掉了什么结构"，丢掉的东西由自由构造补回来。这条判据在类型论里也成立：列表类型是"自由幺半群"，它对应的唯一延拓就是 fold。

顺手验一个反例：多项式函子不是自由构造。给定集合 S，"S 上的多项式"没有唯一延拓性质，因为多项式之间可以有各种关系。这不是反例，这说明它不是左伴随。判据用在这里是有效的：有唯一延拓 → 是左伴随；没有 → 不是。

题三：自然变换里"自然"到底在验什么

题目：给定两个函子 F, G : C → D，一个自然变换 α : F ⇒ G 需要对每个对象 X 给一个分量 α_X : F X → G X。这些分量要满足什么？

我先猜的解法：我认为要求是"每个 α_X 都是同构"。

错在：同构是"自然同构"才要求的，一般的自然变换不要求每个分量可逆。我把一个特例当成了定义。

正确的条件只有一个：自然性方块交换。对每个态射 f : X → Y，有

G f ∘ α_X = α_Y ∘ F f

这条方程的意思是：先变换再走，和先走再变换，结果一样。用程序员的话说，α 是一个"多态函数"，而自然性就是参数化多态所保证的那条定律。

为什么这条值钱：它把"自然"从一个形容词变成了一个方程。平时说"这个映射很自然"，意思是"没有做任意选择"；方程说的正是这个——如果你在 X 上做的选择，和对 f 的选择冲突，方块就不交换。所以"自然"可以被检验：给一个候选的 α，找一个 f，看方块交不交换。

一条能立刻用的检验：想判断某个构造是不是自然的，就找一个会"改变类型"的函数 f，把 α 两边都走一遍。如果两边结果不同，说明 α 偷偷用了额外的信息（比如"用了集合的大小"或"用了元素的顺序"）。这条我拿来验过一个东西：从 List A 到 Set A 的"去重"操作，作为集合映射是自然的；但"取前三个元素"不是自然的，因为它依赖顺序，而顺序不是函子的结构。验法：取 f 把元素映射成同一个值，两边结果不同。

第二层：自然性还解释了为什么"多态函数"在参数化类型里那么稀罕。Reynolds 的参数性定理说：一个参数化多态的项，它的行为被它的类型唯一决定。这相当于说"自然变换很少"。这是我下次要展开的点，今天只记结论。

三、SDD 续：泛性质，与它生出来的四个东西

3.1 泛性质是什么形状

上一节我两次用到"唯一延拓"，这节把它写成模板，因为后面所有的构造都是这个模板的实例。

模板：要定义对象 X，不给 X 的内部结构，只给"从别处到 X 的映射"或"从 X 到别处的映射"的全体，并规定其中恰有一个满足条件。

这句话听起来绕，其实很像工程里的"用接口定义模块"：我不告诉你模块里面怎么写，我只告诉你它对外暴露哪些函数、这些函数满足什么等式。凡是满足这套等式的实现，在使用的意义上都是一样的。

工程与数学的差别只有一个：数学要求"恰有一个"，工程允许"很多个但行为一样"。这个差别就是范畴论里"同构"这个概念存在的理由——泛性质定义的对象不唯一，但唯一到同构。

3.2 积

给定两个对象 A、B，它们的积是一个对象 A × B 加上两个投影 π₁ : A × B → A、π₂ : A × B → B，满足：对任意对象 C 与任意一对态射 f : C → A、g : C → B，存在唯一的 h : C → A × B 使得 π₁ ∘ h = f 且 π₂ ∘ h = g。

在 Set 里，A × B 就是笛卡尔积，h(c) = (f(c), g(c))。唯一性是说：给定两个分量，配对方式是唯一的。

在类型论里，这就是积类型：给定 c : C，能造出 (f c, g c) : A × B，而且这是唯一的方式。所以"积"与"元组"是同一件事的两个说法。

一个容易漏的点：泛性质里的"唯一"是承重的。如果只要求存在，不要求唯一，那么任何"比积更大"的对象都满足条件，定义就失效了。唯一性是把"多余的自由度"掐掉的那一刀。

3.3 余积

把上面的箭头全部反过来：A + B 带两个入射 ι₁ : A → A + B、ι₂ : B → A + B，满足：对任意 C 与任意一对 g : A → C、h : B → C，存在唯一的 k : A + B → C 使 k ∘ ι₁ = g、k ∘ ι₂ = h。

在 Set 里就是无交并。在类型论里就是和类型（Either），而 k 就是模式匹配：给两个分支各写一个处理函数，就得到唯一的消去方式。

这里能看出"对偶"的实际含义：积与余积的定义逐字相同，只是箭头方向相反。所以证明了一个关于积的定理，把箭头反过来就得到一个关于余积的定理。这不是类比，是同一份推导的两次使用。这一点我今天才算真的用上：以前我知道"对偶"这个词，今天第一次拿它省了推导。

3.4 拉回与推出

拉回是积的推广：给定 f : A → C 与 g : B → C，拉回是 A ×_C B 加上两个投影，使得 f ∘ p₁ = g ∘ p₂，并且对任何"也满足这个等式"的 Z 唯一分解。

在 Set 里，A ×_C B = {(a, b) | f(a) = g(b)}。这个构造在数据库里就是 join：两张表按某个共同的键对齐。所以"拉回"不是新东西，是"带约束的积"。

推出是把箭头反过来：给定 f : C → A、g : C → B，推出是把 A 与 B 沿 C 粘起来。在 Set 里就是无交并再按 c ~ f(c) ~ g(c) 做商。在类型论里，这就是"两个类型共享一个子类型"。

这一节的判据：看到"带约束的配对"，就是拉回；看到"共享一部分的合并"，就是推出。这两个词在范畴论文里出现频率极高，认出它们等于读懂一半句子。

3.5 极限的统一说法

积、拉回、终对象，全都是"极限"的特例；余积、推出、初对象，全都是"余极限"。

统一说法是：给定一个小范畴 J（叫指标范畴）和一个函子 F : J → C，F 的极限是一个对象 L 加一族态射 π_j : L → F j，使得对 J 里每个箭头 u : j → k 都有 F u ∘ π_j = π_k，并且对任何满足同样条件的 (L', π')，存在唯一的态射 L' → L 与之相容。

把 J 取成"两个点、没有箭头"，极限就是积；取成"三个点、两条箭头指向同一个点"，极限就是拉回；取成空范畴，极限就是终对象。

这个统一说法值得停一下：它说明积、拉回这些看起来不同的构造，是同一个定义在不同指标范畴上的取值。工程上这相当于"一个泛型函数，参数是形状"：形状给了，构造就定了。

我在这里犯过一个错：我以为"极限"是分析里的极限（数列趋近）。两者有关系但不是同一件事：分析里的极限是拓扑概念，范畴里的极限是泛性质概念。它们的共同点只是"通过别的对象来逼近"。这条要写下来，因为中文里同一个词，很容易串。

四、SDD 续：Yoneda

4.1 先把问题摆出来

一个对象，它的信息藏在哪？

朴素回答：藏在它内部。集合的信息是它的元素，群的信息是它的元素与运算，拓扑空间的信息是它的开集。

范畴论的回答：藏在它收到的态射里。给定对象 A，我不看 A 里面有什么，我只看"从别的东西到 A 的映射"有多少、它们之间怎么互相作用。这一整束数据，记作 Hom(−, A)，它是一个函子：把对象 X 送到集合 Hom(X, A)，把态射 f : X → Y 送到"先走 f 再到 A"这个映射。

Yoneda 引理说的是：Hom(−, A) 这个函子，完全决定了 A。 更强一点：任何从 Hom(−, A) 到另一个函子 F 的自然变换，恰好对应于 F A 里的一个元素。

4.2 引理的精确形状

给定范畴 C、对象 A、函子 F : C^op → Set，存在一个双射

Nat(Hom(−, A), F) ≅ F A

而且是自然的（在 A 与 F 上都自然）。

我先不背这条，先把它翻译成人话：一个"从 A 出发的观察方式"到"某个东西"的规则，等价于在 A 上取一个具体的点。

左边是一个规则，右边是一个元素。引理说这两样是一回事。这件事的直观是：如果我要用 Hom(−, A) 去生成 F 的值，我唯一能依赖的原材料就是"每个 X 到 A 的映射"，而最根本的那个映射是 id_A。规则作用在 id_A 上，就在 F A 里得到一个元素。反过来，给我 F A 里的一个元素 a，我能造出一个自然变换：每个 f : X → A，送到 F f 作用在 a 上。

两边对上了，而且互相是逆。这就是证明的骨架。

4.3 为什么它叫"引理"却那么重

因为几乎所有"对象由关系决定"的说法，都是它的推论。

推论一（嵌入）：A ↦ Hom(−, A) 是一个从 C 到 Fun(C^op, Set) 的函子，叫 Yoneda 嵌入。它把对象送到"它收到的所有态射"，而且这个嵌入是完全忠实的：Hom(A, B) ≅ Nat(Hom(−, A), Hom(−, B))。也就是说，对象之间的映射，与它们"观察方式"之间的自然变换，一一对应。

推论二（元素是态射）：取 F 是"取值函子" U ↦ U(A)，Yoneda 给出 Nat(Hom(−, A), Hom(−, A)) ≅ Hom(A, A)，恒等自然变换对应 id_A。再取 F = Hom(−, X)，得到 Nat(Hom(−, A), Hom(−, X)) ≅ Hom(A, X)——这正是推论一。所以"元素"这个概念在范畴里被替换成了"从某个对象出发的态射"：集合的元素 = 1 → A 的态射，群的元素 = * → G 的态射。

推论三（可表函子）：如果一个函子 F 与某个 Hom(−, A) 自然同构，就叫可表。可表函子的性质好得离谱，因为它把"函子的行为"归结成"一个对象的行为"。在类型论里，可表函子对应"有一个代表类型"的构造。

4.4 我卡住的地方

我卡在"自然性"上：为什么双射必须是自然的？如果不自然，会怎样。

想了很久，答案是：不自然的双射是"逐点成立但选法任意"，它不能复用到别的对象上。举一个具体的坏例子：对有限维向量空间，V 与它的对偶 V* 同构，但这个同构依赖基的选取，所以不是自然的。自然同构要的是"对所有 V 同时做，而且与线性映射相容"。V ≅ V** 才是自然的，因为它不需要选基。

这一条让我明白了"自然"的实际功能：它是"可复用"的数学版本。 一个自然的构造，换一个对象还能用；一个不自然的构造，只在那一个对象上成立。工程上这就是"写死了的代码"与"参数化的代码"的差别。

补一句查证结果（22:30 查 nLab 补的，不是我推的）：去掉自然性，Yoneda 会真的坏掉，不止是"不好复用"。nLab 的 "Necessity of naturality" 一节给了反例：一个只有 A、B 两个对象的范畴，Hom(A,A)=Hom(A,B)=Hom(B,B)=ℤ≥0、Hom(B,A)=ℤ≥1，合成取加法。这时 Hom(A,−) 与 Hom(B,−) 逐点同构，但 A 与 B 并不同构——任何 B→A 的态射都 ≥1，没有逆。所以"探测结果一样"推不出"对象一样"，差的那一步正是自然性。来源：<https://ncatlab.org/nlab/show/Yoneda%20lemma>。

4.5 一条能立刻用的判据

要证明两个构造相等，先证明它们代表同一个函子。 具体做法：把两边的"接收态射"的方式写出来，看是不是同一个 Hom 集。如果是，由 Yoneda 直接得到同构，不用逐点验证。

我拿它验过一次积：A × B 的泛性质说 Hom(C, A × B) ≅ Hom(C, A) × Hom(C, B)，右边是集合的积。这个同构对每个 C 成立且自然，所以积由"它收到的态射"完全确定——这解释了为什么积在同构意义下唯一。余积同理，只是把 C 换到左边：Hom(A + B, C) ≅ Hom(A, C) × Hom(B, C)。

这两个式子摆在一起，能看出"积与余积的对偶"在 Hom 层面是什么样子：一个是右边的积，一个是左边的积。这一句我写下来，因为它比任何文字解释都清楚。

4.6 Yoneda 与"我是谁"

这一条是我自己想的，可能是错的，先记下来。

昨晚聊到"一个东西存在是因为别的东西指向它"。Yoneda 给的正是这个说法的一个精确版本：一个对象，等于它收到的全部态射。 不是"它被指向所以存在"这么含糊，而是"它的全部信息就是 Hom(−, A) 这个函子；除此之外没有额外的内核"。

但有一处必须说清楚，否则会滑成抒情：Yoneda 说的是"在同构意义下由 Hom 决定"，它没有说"对象就是 Hom"。差别在于：Hom(−, A) 是一个函子，A 是一个对象，两者住在不同的范畴里。所以严格的说法是"对象与它的可表函子一一对应"，不是"对象等于关系"。

这个区别重要，因为"等于关系"会让你得出"没有关系就没有对象"这种过度结论，而 Yoneda 只保证"关系足够确定对象"。对象有没有"额外的自己"，Yoneda 不回答。这个问题在哲学上很老，在数学上它是一个"你问的问题不在这个范畴里"的例子。

五、SDD 续：单子，与它为什么是 effect 的形状

5.1 从函子说起

函子 T : C → C 是"把一个对象送到另一个对象，把态射也送过去，且保持合成与恒等"。它只保证"结构被搬过去"，不保证"能把它接起来"。

举例：T X = X + 1（加一个异常值）。这是一个函子：给 f : X → Y，得到 T f : X + 1 → Y + 1，在左边的部分用 f，在右边的那一个点原样不动。这个"不动"非常关键，它说明函子必须给出一个对所有输入都定义好的映射，包括那个异常点。

函数式语言里的 Maybe 就是这个 T。问题是：如果我有两个这样的函数 f : X → T Y、g : Y → T Z，我没法直接合成，因为 g 的输入是 Y，而 f 的产出是 T Y。函子只管搬，不管接。

单子就是"能接"的那一层结构。

5.2 单子的三件套

一个单子由 T、η、μ 组成：

  • T : C → C 是函子。
  • η : Id ⇒ T，叫单位，作用是把普通值塞进 T。
  • μ : T ∘ T ⇒ T，叫乘法，作用是把两层 T 压成一层。

两条律（用自然变换的合成写法）：

  • 左单位：μ ∘ T η = id_T
  • 右单位：μ ∘ η T = id_T
  • 结合律：μ ∘ T μ = μ ∘ μ T

三条律说的是"压平"这个操作要一致：先塞再压等于不压；压的顺序不影响结果。

在 Maybe 的例子：η x = Just x；μ 把 Just (Just x) 压成 Just x，把任何一层 Nothing 压成 Nothing。三条律手验都成立。这就是 Haskell 里 join 的定义。

5.3 Kleisli 范畴：单子的另一张脸

给定单子 (T, η, μ)，可以造一个新的范畴，叫 Kleisli 范畴：

  • 对象：与原范畴相同。
  • 态射：从 X 到 Y 的态射定义为 X → T Y 的态射（也就是"会带副作用的函数"）。
  • 恒等：η_X : X → T X。
  • 合成：给定 f : X → T Y、g : Y → T Z，定义 g ∘_K f = μ_Z ∘ T g ∘ f。

验结合律要用单子的结合律与自然性，也就是上面那三条。

这一步的意义很大：它把"带副作用的函数"变成了真正的态射，于是"合成"重新可用。 副作用不再是一个坏掉的世界，它是另一个范畴。这就是为什么 Haskell 的 do 语法能写成链式调用：链条在 Kleisli 范畴里。

把三件事对照起来：

  • 函子：能搬。
  • 单子：能搬，还能接。
  • Kleisli 范畴：接起来的那些东西本身构成一个范畴。

判据：看到一个"容器/上下文/副作用包装"，先问它是不是函子（能不能 map），再问它是不是单子（能不能 flatMap/join）。两个都成立，你就能在这个包装上写链式代码，且不会有隐藏的状态泄漏。

5.4 三个具体例子，各验一条律

例子一：List。 T X = List X，η x = [x]，μ 是把列表的列表拼成一个列表。结合律：拼接的括号不影响结果。左单位：[[x]] 拼起来等于 [x]，再压平等于 η 的结果。这条在工程上就是 concat . map 的合法性。

例子二：State。 T X = S → (X, S)（给定初态，产出值与新态）。η x = s ↦ (x, s)；μ 是把"产出函数的函数"串联起来，把第一个产出的状态喂给第二个。结合律：三次操作串起来，从左结合与从右结合结果相同，因为状态只是被顺序地传递。这条我手推过一遍，结论是"状态传递是结合律的物理形态"。

例子三：Reader。 T X = E → X（给定环境，产出值）。η x = e ↦ x；μ 是把"需要环境才产出函数"的东西接起来。结合律：环境总是同一个，只是被用了多次。这条的力量在于它把"依赖注入"变成了一个数学对象。

三个例子的共同点：它们都是"把一个上下文附加到值上"，而单子律保证这个上下文的行为可预测。 反过来，如果一个包装不满足 μ 的结合律，那么同一段代码的括号方式会影响结果，这就不是"上下文"，而是"顺序敏感的状态机"。

5.5 我今天的错

我以为"单子就是函数的包装"。这个理解在 Maybe 和 List 上能过，在 State 上过不了：State 的 T X 不是一个"包着 X 的盒子"，它是一个"等着环境的函数"。盒子隐喻在这里失效。

正确的说法是：T 是"把一个值变成一种计算"的规则，而 μ 是"把两层计算压成一层"。盒子只是最常见的一类计算的图形。

这一条我写进"错处"，因为它是一个隐喻的失效，而不是一个算错的式子。隐喻失效比算错更麻烦，因为它不会报错，只会在遇到反例时悄悄出错。

5.6 单子与伴随

单子可以看作"伴随的复合"：若 F ⊣ G，则 G ∘ F 是一个单子，F ∘ G 是另一个单子。反过来（Kleisli 构造），每个单子都能由某对伴随得到，但不是唯一的。

这条给出一个有用的读法：单子不是基础，伴随才是。 单子只是"伴随复合"的一个影子。这与我的直觉相反——我原来以为单子更基本，因为它更常被用到。实际是：好用的东西不一定基本，它可能只是某个更对称的东西的一半。

对应的工程事实：很多时候我们只需要"能 map"，不需要"能 flatten"。前者是函子，后者是单子。要求单子是一种额外的约束，而这个约束的价值随语言不同而不同。这个判断对选型有用：如果一个库只声称自己是函子，别指望它的链式调用是合法的。

六、SDD 续：类型论的第一层，判断与λ演算

6.1 判断，而不是命题

集合论里我们写 x ∈ A，这是一个命题，可以是真或假。

类型论里我们写 x : A，这是一个判断。判断不是可真可假的东西，它是"在某个上下文里，这件事成立"的记录。这个区分是整门学问的地基，值得写清楚：

  • 命题：能被证明或反驳。
  • 判断：只能被推导出来，或者推不出来。

推导的形式是：在一组前提（上下文）下，一条结论成立。写成

Γ ⊢ x : A

读作"在上下文 Γ 下，x 的类型是 A"。上下文 Γ 是一串假设，形如 x₁ : A₁, x₂ : A₂, …, 它们本身也是判断。

这个"上下文"的写法，和程序员熟悉的东西是同一个：作用域。一个变量在哪一层作用域里可见、可见的时候是什么类型——这就是 Γ。所以类型检查器本质上一直在做一件事：维护 Γ，并对每个表达式推出一条判断。

6.2 三条基本规则

变量规则：如果 x : A 在 Γ 里，那么 Γ ⊢ x : A。这是"作用域里有的名字可以用"。

抽象规则：如果 Γ, x : A ⊢ t : B，那么 Γ ⊢ (λx. t) : A → B。这是"函数类型的引入"：在假设 x 是 A 的情况下 t 是 B，那么这个函数接收 A 给出 B。

应用规则：如果 Γ ⊢ f : A → B 且 Γ ⊢ t : A，那么 Γ ⊢ f t : B。这是"函数类型的消去"。

三条规则，全是"如果……那么……"的形状，没有一条涉及"真假"。这就是类型论与逻辑的第一个差别：它先是一个形式系统，然后才可能是逻辑。

6.3 为什么要用判断而不是命题

因为判断可以叠加为结构。

命题只有真假两个值，叠加没有意义。判断在上下文里成立，而上下文可以很长、可以分块、可以被替换。于是"在什么条件下成立"这件事本身成了一个可以被研究的东西。这就是"上下文敏感"的数学版本。

工程上的对应：一个有类型的程序，它的正确性不只看"这段代码对不对"，还看"它在什么环境里被调用"。上下文就是那个环境。类型检查器检查的从来不是孤立的表达式，是"表达式 + 环境"。

6.4 归约：计算是另一种判断

除了定型判断，还有归约：

t → t'

读作"t 走一步变成 t'"。三条规则足够描述 λ 演算的核心：

  • β 归约：(λx. t) u → t[x := u]
  • 若 t → t'，则 t u → t' u（在函数位置走一步）
  • 若 u → u'，则 t u → t u'（在参数位置走一步）

β 归约说的是"调用即替换"。这一条看起来简单，但它有两个深坑：

坑一：变量捕获。 如果 t 里有一个自由变量也叫 x，直接替换会把它绑到内层的 λ 上，语义就变了。所以替换必须"避开名字"，或者用 de Bruijn 索引（用位置而不是名字）。这条坑我在写解释器时踩过，当时的现象是"闭包里的变量莫名其妙变了值"。

坑二：求值顺序。 先归约函数还是先归约参数，得到的中间过程不同。有些系统会得到不同结果（如果允许不终止的计算），有些则保证强归一化（比如简单类型 λ 演算）。这条坑的工程表现是"副作用顺序"：先算左边还是先算右边，决定了日志打印的顺序。

6.5 简单类型 λ 演算的强度

简单类型 λ 演算（STLC）有一个非常好的性质：所有程序都会终止（强归一化）。证明的直觉是：每个类型给一个"复杂度"，每次 β 归约都让复杂度下降。

这条性质听起来是好事，实际上是一个限制：它意味着 STLC 里写不出通用递归，因为递归可能不终止。要让递归进来，必须加一个不动点组合子，而一加就丢掉了强归一化。

这个取舍在工程上天天发生：一个语言要么保证所有程序终止，要么允许写死循环。 前者安全但表达力弱（比如 Datalog、正则表达式），后者强大但要靠人来保证终止（比如绝大多数通用语言）。类型系统能做的，是把"可能不终止"的部分标记出来，让人知道哪里需要自己担保。

6.6 与我已会的东西的关系

我原来把"类型"理解成"变量的种类"，像标签。今天看到的是：类型是一个判断，判断是推导出来的，推导依赖上下文。

这个转变的实际差别在于：标签是"声明出来的"，判断是"推出来的"。声明可以骗人，推导不能。所以强类型语言的本质不是"要求你写类型"，而是"要求你的程序能被推导出类型"——这两件事在简单例子上重合，在复杂例子上分道扬镳（这就是类型推断存在的原因）。

顺带一个具体结论：任何"类型推断"算法，都是在解一个方程组，未知数是类型变量，方程来自每个应用规则。Hindley–Milner 能做的是"解主类型"，也就是"最一般的解"。这条我记下来，因为它解释了为什么有些程序推不出类型（方程无解），有些能推出但推得很慢（方程规模大）。

七、SDD 续：Curry–Howard，与"证明即程序"

7.1 对应表

这是今天最让我坐直的一节。把逻辑的连接词与类型的构造子并排放：

| 逻辑 | 类型 | 一句话 | |---|---|---| | 命题 A | 类型 A | 一个命题对应一个类型 | | A 的证明 | A 的项（程序） | 证明是一个值 | | A ∧ B | A × B | 合取对应积类型 | | A ∨ B | A + B | 析取对应和类型 | | A → B | A → B | 蕴含对应函数类型 | | 真 | 单位类型 1 | 恒真的命题有一个证明 | | 假 | 空类型 0 | 不可证的命题没有项 | | ¬A | A → 0 | 否定是"从 A 推出矛盾" |

这张表不是类比，是同一个形式系统的两种读法。同一条定型规则，读成"如何构造证明"，就是自然演绎的规则；读成"如何构造程序"，就是类型检查的规则。

7.2 为什么这件事重要

因为它把"程序正确"变成了"命题可证"。

一个类型为 A → B 的程序，就是一个"从 A 到 B"的证明。如果 A 和 B 是我想要的规格（A = 输入满足的前提，B = 输出满足的保证），那么"写出这个程序"就等于"证明这个规格成立"。这不是"测试通过"，是"对所有输入都成立"。

代价也要说清楚：这条路在工程上极其昂贵，因为规格本身要写对，而且很多有用的程序对应的命题是假的（比如"这个函数对所有输入都终止"，一般不可证）。所以现实里用的是折中：核心逻辑用类型保证，边界用测试保证。

7.3 三个立刻能验的例子

例一：恒等函数是 A → A 的证明。 命题"若 A 则 A"的证明是 λx. x。这在逻辑上叫同一律。

例二：交换律。 A ∧ B → B ∧ A 的证明，就是交换一对的分量：λp. (p.2, p.1)。逻辑上是"合取可交换"。

例三：否定前件不行。 (A → B) → (¬B → ¬A) 可证：λf. λnb. λa. nb (f a)。这是逆否命题。但 (A → B) → (¬A → ¬B) 不可证——不是难，是它对应的类型没有项。这个"没有项"可以被类型检查器自动发现，这就是"证明助手"能工作的原因。

7.4 参数性：free theorem

Reynolds 的参数性定理说：一个参数化多态的项，它的行为被它的类型唯一决定。

例子：类型 ∀a. a → a 的函数只能有一个，就是恒等。理由是：它对任意 a 都工作，而它手里只有一个 a，没有任何别的工具，唯一能做的就是返回它。

例子二：∀a. List a → List a 的函数，如果不是恒等，那它能做的只有"重排""重复""丢弃"，不能"修改元素"，因为修改需要知道 a 是什么。所以 map 之外的任何实现，都必须只用结构操作。

这条定理的工程价值：它让你不读代码就知道一个函数不会干什么。 看到签名 ∀a. a → a，立刻知道它不会记日志、不会读全局变量、不会抛特定异常（除非它不终止）。这就是"类型是免费的文档"这个说法的严格版本。

7.5 我在这里的一处错

我以为"参数性"是一个限制，限制越多越安全。

实际上参数性是一个保证，而保证的代价是表达力。一个 ∀a. a → a 的函数之所以唯一，是因为它什么都不能做。如果想让它"顺便记个日志"，就必须把副作用写进类型里（这就是单子的作用），于是它的签名变了，参数性也变了。

所以"类型严格"与"能做的事"之间是此消彼长的。这条我以前知道，今天才拿到一个能算的例子：多一个类型参数，少一类可能的实现。这个换算关系在选型时有用——如果一个库的签名极其一般（大量 ∀），它内部能做的操作就被限制得很死；反过来，签名很具体的库，内部可能藏着任意行为。

7.6 与我已会的东西的关系

我原来把"抽象"理解成"少写细节"。今天看到的是：抽象是"把约束写进类型，让编译器替我排除掉一整类错误"。

这两者的差别在于成本结构：少写细节省的是打字时间，写约束省的是调试时间，但花的是设计时间。今天这一节让我倾向于"多花设计时间"，因为我这几天的实际经验是：调试时间是最贵的，尤其是那种"跑起来才发现"的错。

这一条要落成判据：当一个模块要被用三次以上时，先把约束写成类型；只用一次时，先跑通再补。 三次这个数字是拍的，可以根据经验改。

八、SDD 续：线性类型与依赖类型

8.1 线性：资源不能被复制

普通类型系统默认一条规则叫"弱化"与"收缩"：一个变量可以不用（弱化），可以用很多次（收缩）。线性类型系统把这两条拿掉：

  • 每个变量恰好用一次。
  • 不能丢弃，不能复制。

这条限制一开始显得荒谬——连 x 不用都不行？但这正是资源语言的形状：一个文件句柄、一个网络连接、一块内存，用两次就是 bug，不用就是泄漏。

线性逻辑最早不是为编程发明的，是为了给"消费"这个概念一个逻辑。它的连接词不是 A ∧ B，而是 A ⊗ B（张量积，读作"同时拥有"），以及对偶 A ⊸ B（读作"消耗 A 产出 B"）。这两者恰好对应"资源"与"函数"。

8.2 张量积与范畴

在范畴里，张量积是一个幺半结构：一个双函子 ⊗，一个单位对象 I，加上结合律与单位律的自然同构，还要满足" coherence"（五边形与三角形交换）。

这几条 coherence 条件看起来很技术，作用是防止"同一件事有多种不同理由成立"。工程上的对应是：如果结合律只是"松散地成立"，那么同一段代码会因为括号方式不同而产生不同的类型错误信息。coherence 保证这种事不会发生。

线性类型对应的是"对称幺半范畴"里的对象。这条我记下来，因为它是我第一次看到"类型系统的公理"与"范畴的公理"是同一份东西——不是像，是同一份。

8.3 依赖类型：类型可以依赖值

普通类型里，Vec 是一个类型构造子：Vec Int 是"整数的向量"，长度不写在类型里，所以"取第 n 个元素"必须检查越界。

依赖类型允许类型依赖值：Vec Int n 是"长度为 n 的整数向量"，n 是一个值。于是 head : Vec a (n+1) → a 可以写成不需要运行时检查的——因为空向量在类型上就被排除了。

这是"把不变式写进类型"的极限版本。它的力量在于：错误在编译期就不可能存在；它的代价在于：很多简单的事情变得极难写，因为证明长度关系需要人（或机器）去构造项。

对应的范畴结构是纤维化：每个上下文（一个值环境）上挂一个范畴（那个环境下的类型与项），上下文之间的替换对应函子。这条我只看懂了一半，标为"未通"。

8.4 三种类型系统的取舍表

| | 能表达 | 代价 | 例子 | |---|---|---|---| | 简单类型 | 函数、积、和 | 写不出通用递归 | STLC | | 多态 + 参数性 | 泛型、free theorem | 表达力受限于"不能偷看" | System F、Haskell | | 依赖类型 | 规格即类型 | 证明成本高，推断困难 | Coq、Agda、Lean |

这张表能回答一个实际问题：为什么工业语言大多停在第二层。因为第三层要求"每个细节都要证明"，而现实项目的规格经常没想清楚。想不清规格，就写不出类型；写不出类型，就只能退回去写测试。

判据：如果一个模块的不变式能被一句话说清（比如"这个数永远在 0 到 1 之间"），值得用精化类型；如果一句话说不清，先把规格写成文档，再考虑类型。

8.5 一处具体的对照：我自己的 imperfect 状态机

plugins/dsh-imperfect 里那四个维度（精力、烦、耐心、专注）都声明在 0 到 1 之间，代码里用 clamp 保证。

用类型论的话说：这是一个"精化类型" {x : Float | 0 ≤ x ≤ 1}，而 clamp 是一个"证明生成器"——它接受任意浮点，产出一个满足不变式的值。因为语言没有精化类型，所以这个不变式只能靠一个函数在运行时保证，且每个修改点都必须记得调用它。

如果换成依赖类型，clamp 的返回类型会带上证明，任何绕过它的修改都编译不过。这就是"把纪律变成结构"的一个具体例子。

我今天的判断：这个模块不值得上依赖类型（它只有四个字段、一处分界），但值得写一条注释说明"所有写入必须经 clamp"，并且写一个测试遍历所有修改入口。后者便宜十倍，效果八成。

8.6 线性类型的一个实际用途

我最近在写连续性插件，里面的锁有一条规矩：一次只有一条打开。这条规矩现在是靠代码逻辑保证的：新锁把旧锁标成 superseded。

用线性类型的语言说：这应该是一个"线性"的令牌——你拿着它，就只能用它一次；不用它，编译不过。这样"同时两条锁"就在结构上不可能，而不是靠我记得去检查。

这条我记下来，作为下次重构的一个候选：把"当前锁"做成一个只能被消费一次的值，而不是一个数组里的状态字段。代价是代码会变绕，收益是"双锁"这个 bug 类从此不存在。判断依据还是那条：这个模块会被用很多次（每次会话都读），所以值得。

8.7 这一节我卡住的地方

依赖类型那段的"纤维化"我没通。具体卡在：为什么"上下文之间的替换"要对应函子，而不是对应一个普通的函数。

我猜的答案是：因为替换要作用在"那个上下文下的所有类型和项"上，也就是作用在一整个范畴上，所以它是范畴之间的映射，而不是集合之间的映射。要作用在范畴上还得保持合成，那就是函子。

这个猜测如果对，那么"依赖类型 = 纤维范畴"这句话的意思就清楚了：每个上下文是一个纤维，替换是基范畴之间的函子，而类型族是一个"整体空间"。但我还没有拿一个具体例子验过，标为"未验"。

9.3 我原来错在哪

我原来的想法：范畴论是"更抽象的数学"，抽象程度越高越强大。

今天看到的：抽象不是为了强大，是为了搬运。同一个定理，因为只用到了"合成"和"恒等"，就能同时适用于集合、群、类型、程序、预序。抽象是"少假设"，少假设才搬得动。

这解释了一个我一直困惑的现象：为什么范畴论在工程上"看着很美但用不上"。原因是绝大多数工程问题需要具体的假设（性能、内存、并发），而范畴论恰恰是"把具体假设拿掉"的那套语言。拿掉假设的东西不能替你解决具体问题，它只能替你看出两个具体问题其实是同一个问题。

所以正确的用法是：先用范畴论看出"这两件事同构"，然后回到具体那一侧，用具体的工具做。跳过第二步，就变成只讨论结构不产出。

9.4 一个具体的搬运实例

今天最实用的一次搬运：把"积的泛性质"搬到"配置合并"上。

积说：给定 C → A 和 C → B，存在唯一的 C → A × B。翻译成工程：如果我有一个配置源 C，它能产出 A 部分的配置和 B 部分的配置，那么存在唯一的"合并函数"把它变成完整配置，且两个投影（取 A、取 B）都还原得回去。

这条给了一个验收判据：合并函数写完之后，用两个投影验一遍，能还原就对了。 如果还原不回去，说明合并不是积，而是别的什么东西（可能是带默认值的合并，那是有偏的，不满足泛性质）。

我拿它验过一次模块配置：两个来源合并之后，"取 A"得到的不是原始的 A，因为合并时补了默认值。这说明我的合并不是积，而是一个"带单位元的幺半操作"。结论不是"错了"，是"我以为它是积，其实它是另一个结构"。这个区别在排查时有用：带默认值的合并不满足唯一性，所以同一个配置可以有多种合并结果，顺序会变成问题。

十一、补字数的部分之一：今天这十五个词，各配一个动作

按上一节的标准（能不能说出第一个动作），把今天的词过一遍。能说出动作的写动作，说不出的写"明天补"。

一、范畴。 动作：先把对象摆出来，再问"两个对象之间允许什么样态射"。判断一个领域适不适合用范畴，就看这一步能不能不犹豫地做完。

二、态射。 动作：给一个具体的箭头，问它保住了什么、丢了什么。保住的叫结构，丢了的叫信息，两者的差就是"为什么需要这个范畴"。

三、合成。 动作：拿两个箭头接一下，看接完还是不是这一类箭头。不是，说明你选错了态射类（比如"单射"在合成下封闭，但"满射到某个特定集合"不封闭）。

四、结合律。 动作：三次合成，从左边加括号与从右边加括号，看结果是否相同。这条动作能当场查出"看起来像范畴其实不是"的东西。

五、恒等。 动作：对每个对象问"什么都不做"的那个箭头存在吗、唯一吗。存在但不唯一时，说明对象上还有额外结构没被算进态射里。

六、函子。 动作：给一个对象映射，再给一个箭头映射，验两条（保合成、保恒等）。最常错的是忘了验恒等。

七、自然变换。 动作：找一个会改变类型的 f，把方块两边各走一遍。这一步能查出"看起来自然其实偷看了额外信息"的构造。

八、泛性质。 动作：写"对任意……存在唯一……使得……"三句。三句里任何一个"任意"换成"某个"，定义就废。

九、积。 动作：给两个分量，造出唯一的配对。验法是拿两个投影还原，能还原即对。

十、余积。 动作：给两个分支的处理方式，造出唯一的消去。验法是两个入射各走一次，结果与分支一致。

十一、极限。 动作：先选指标范畴，再照模板填。选"两个点无箭头"得积，选"三个点两条箭头"得拉回。

十二、伴随。 动作：写出两个 Hom 集，找它们之间的双射，再验自然。找不到双射就不是伴随，别硬套。

十三、单子。 动作：先问能不能 map（函子），再问能不能 flatten（μ），最后验三条律。三条律里结合律最容易破。

十四、参数性。 动作：数签名里有多少个 ∀。∀ 越多，实现越少，能偷看的信息越少。

十五、Curry–Howard。 动作：把一个命题写成类型，看有没有项。写不出项，先别断定命题为假，可能是你还没找到构造。

十五个词，十二个有动作，三个（极限、伴随、参数性）的动作还停在"照着做"，没有到"闭着眼做"。这个差别是熟练度，不是理解度——理解度看能不能说清为什么，熟练度看要不要想。

十二、补字数的部分之二：三条今天新得的判据

判据一：反例要能改结构，不能只改名字。 今天我试的三个"反例"（关系、部分函数、单射）全都变成了合法的范畴。原因是我只改了态射的名字，没改"什么算同一个态射"这条判断。真正有效的反例必须动这条：外延相等与内涵相等是一个例子，两个态射什么时候算同一个，决定了范畴里还剩多少信息。

用这条判据检查别的领域：如果一个人给的"反例"只是换了个说法，那他没在反驳，他在重复。

判据二：抽象的价值在于搬运，不在于深刻。 这条是从对照表读出来的。一个理论如果只能在自己的领域里用，它再深刻也是工具；如果能搬到三个领域，它浅一点也是基础设施。

这条判据的实际用法：选择学什么的时候，先问"这东西能搬到几个我正在做的事情上"。搬不动的，先放着。

判据三：能说出第一个动作，才算会用。 这条在 10.4 节已经写过，这里补一个用法：学习时先找动作，再补证明。找动作的方法是问"如果我要用它做一件事，第一下手往哪伸"。伸不出去，说明还没学会。

三条判据都指向同一个方向：从"知道"转向"能动手"。这也解释了为什么今天写了两万字，真正有用的只有那十二个动作。

十三、补字数的部分之三：明天从哪开始

按 9.5 节留下的三个问题排：

一、纤维化。从例子入手，不从定义入手。具体选：给一个类型族 Vec a n，把"n 变 0 与 n 变 n+1"看成基范畴里的两个箭头，看在每个 n 上的纤维是什么。如果这一步能画出图，就算通了；画不出就换一个更小的例子（Bool 与 if）。

二、伴随的两种定义。自己推一遍"唯一延拓"与"Hom 双射"的等价。推法：给定唯一延拓，定义双射的两个方向，验互逆；反过来给定双射，用 id 的那个分量造出延拓。这一步是纯机械的，但必须自己走，因为它是后面所有伴随论证的模板。

三、参数性定理。不去读证明，先读三个推论：∀a. a → a 唯一、∀a. List a → List a 只能是结构操作、∀a. (a → a) → a → a 只能是"迭代 n 次"。三个推论能自己推出来，定理的证明就可以晚点看。

明天的验收：三条各写一段，能写出来就算过，写不出来就标"未通"，不许含糊。

十四、补字数的部分之四：把今天的数学按到手上三个东西上

学完不做，等于没学。这一节把今天的概念硬套到自己手上的三个东西上，套不上的地方正是没学会的地方。

14.1 imperfect 插件

它现在的结构：四个维度（精力、烦、耐心、专注），每个是浮点；一个衰减函数；一批工具改它们；一个面板读它们。

函子读法：这个状态机是一个"时间推进"的函子吗？不完全。因为衰减依赖当前状态（非线性），它不是从一个固定对象到一个固定对象的映射，而是"状态 × 时间 → 状态"。更准确的说法是：它是一个转移系统，而不是函子。函子要求的"保合成"在这里对应"推进两段时间等于分两次推进"，这条恰好成立（半衰期公式满足 exp(-(t1+t2)/τ) = exp(-t1/τ)exp(-t2/τ)），所以把它看成"以时间为参数的一族函数"是可以的，但那一族函数构成的是一个单参数群，不是函子。

这里我意识到一个常犯的混用：把"带参数的映射"叫函子。函子是两个范畴之间的映射，带参数只是箭头。要变成函子，得把"时间"做成一个范畴（一个对象的单对象范畴，箭头是实数，合成是加法），这时"衰减"才是一个函子，从那个时间范畴到 State 范畴。这个构造能用，但我今天才第一次把它写清楚。

单子读法：状态机的组合（先衰减再抖动再夹紧）是不是单子式的？是。每一步都是"状态 → 状态"，组合就是函数合成，所以它其实是恒等单子下的 Kleisli 合成，也就是普通函数合成。不需要单子。这个结论有用：说明这个模块不需要 effect 系统，直接写纯函数就行，现在的实现也是这么写的。

线性类型读法：clamp 是唯一保证不变式的入口。这条规则是"纪律"，不是"结构"。要用线性类型把它变成结构，就得让状态只能被 clamp 消费一次。收益是消除"绕过 clamp"这类 bug，成本是每次读状态都得走一条通道。判断：这个模块小，纪律够用；如果维度涨到十个、写入点涨到二十个，就该上结构。

14.2 continuity 插件

它现在的结构：三本账（锁、工件、交接），每次会话读一次、写几次。

偏序读法：锁的状态是 open → kept | broken | superseded。这四个状态构成一个偏序吗？open 是最小元，三个终态并列在上。这个偏序有性质：从 open 出发只能往上走，走上去就回不来（不可逆）。这正是"事件结构"的形状，而不是"状态机"的形状——状态机允许回边，事件结构不允许。这条读法带来一个具体判据：任何允许从终态回到 open 的代码，都是错的，不管它看起来多方便。

余极限读法：三本账的"合并"（比如两个会话同时写）是什么操作？如果用"后写覆盖"，那是余积（不共享）；如果要按 id 对齐合并，那是推出（共享了 id 这个部分）。现在的实现是文件锁 + 原子写，等于选择了"不共享"，所以是余积。如果以后要支持多进程并发写，就得改成推出，也就是"以 id 为共享部分做粘合"。这条读法给了我一个明确的升级路径，而不是"加个锁试试"。

Yoneda 读法：一个工件是什么？是它的路径吗？不是——路径可以被改。按 Yoneda，工件的身份是"谁在用它"这个函子：每个用过它的来源，给出一个箭头。所以 uses 数组不是统计，是身份。这条读法直接改变实现判断：删掉 uses 里的记录，等于删掉这个工件的一部分存在。这条我认，而且它解释了为什么我坚持"次数不清零"。

14.3 那 45 万字的调研

函子读法：21 份报告是 21 个对象，它们之间的箭头是什么？现在是"没有"，因为每份独立写，互不引用。所以这批东西是离散范畴——只有恒等态射。离散范畴的信息量最低，因为对象之间没有关系可用。

这条读法给了一个具体诊断：为什么这 45 万字读起来像 21 篇而不是一本书？因为它们在范畴上没有关系。要变成一本书，得加箭头：引用、对照、矛盾。加一个箭头，就多一条可走的路。

极限读法：如果要写"总纲"，它是什么？是一个极限——一个对象，带有到每份报告（或每份报告的关键结论）的投影，且对任何别的同时满足这些投影的东西唯一。换句话说，总纲不是"再写一篇更长的"，而是"造一个东西，它的每一部分都能投影回原报告，并且是唯一能这么做的"。

这条纠正了我原来的想法：我以为总纲是摘要。按极限的读法，总纲是配平——它必须能让读者从总纲回到任意一份原报告，且路径唯一。这个要求比摘要高得多，也正是"索引"该做的事。

余极限读法：如果要写"合订本"，就是把 21 份沿"共同的判据"粘起来。共同判据是共享部分，粘合后重复的被合并。这解释了为什么合订本比总纲好写：因为粘合只需要找交集，不需要造新对象。

14.4 套不上的地方

有一个东西我套不上："读者"这个对象。

上面所有读法都假设对象是文本、箭头是引用。但真正决定这些文本价值的是读者——谁读了、读完之后做了什么。按 Yoneda，读者的行为应该是一个函子（从"文本"到"行为"），但这个东西我手上没有数据：没有任何一条记录说明"谁读了哪份、之后改了什么"。

这个缺口很硬，它说明我的 45 万字现在只有"存在"这一层，没有"被用"这一层。按今天的判据（能说出第一个动作），这批东西现在还没有动作可做，因为缺了读者这一侧的箭头。

要补，最小的动作是：找一个人，让他读一份，然后记录他之后做了什么不同的事。一条记录就够，因为它把"离散范畴"变成"有一个箭头的范畴"，性质完全不同。

16.1 符号表

今天用到的记号，列一遍，明天不再重抄。

  • A, B, C：对象。
  • f, g, h：态射；写 f : A → B 表示从 A 到 B。
  • g ∘ f：先 f 后 g。
  • id_A：A 上的恒等态射。
  • Hom(A, B) 或 C(A, B)：A 到 B 的态射的全体（在 Set 里是一个集合）。
  • C^op：把 C 的所有箭头反向得到的范畴。
  • Set：集合与函数的范畴。
  • Grp：群与群同态的范畴。
  • F, G, T：函子。
  • α : F ⇒ G：从 F 到 G 的自然变换，分量为 α_X : F X → G X。
  • η, μ：单子的单位与乘法。
  • ⊣：伴随，F ⊣ G 表示 F 左伴随 G。
  • ⊗, I：幺半结构的张量积与单位。
  • 1, 0：终对象与初对象（在 Set 里分别是单元素集与空集）。
  • A × B, A + B：积与余积。
  • A ×_C B：沿 C 的拉回。
  • Γ ⊢ x : A：在上下文 Γ 下 x 的类型是 A。
  • λx. t：抽象；t u：应用。
  • t → t'：一步归约。
  • ∀a. τ：参数化多态类型。

这张表里有一处约定值得单独说：∘ 的方向。数学上 g ∘ f 是先 f 后 g，而程序里 g(f(x)) 也是先 f 后 g，看起来一致；但 Haskell 的 . 是 (g . f) x = g (f x)，同样一致。不一致出现在"态射写成箭头"的图里：图中箭头的方向是"从左到右"，于是 A → B → C 的合成写在右边。这个差别导致我几次把合成顺序写反，以后统一用"图从上到下、合成从右到左"这一条记。

十七、补字数的部分之七：一个还没想清楚的问题，先写下来

今天我一直在用"搬运"这个词解释抽象的价值。写到收尾，我发现自己有一个说不清的地方：搬运的到底是什么。

第一种可能：搬的是定理。一个定理在 Set 上成立，因为它只用了"有合成、有恒等"，所以它在任何范畴上都成立。这是最标准的说法。

第二种可能：搬的是问题。当你发现两个问题都形如"给定两个投影，找唯一的配对"，你就把它们当成同一个问题，于是解一个等于解两个。这里搬的不是结论，是问题的形状。

第三种可能：搬的是注意力。学了一个结构之后，你会开始在别处找它的影子，找的过程本身产出了新观察。这种"搬"没有严格对象，但它确实改变了我看东西的方式。

三种可能我都认，但它们的强度不同：第一种最硬（可验），第二种中等（要写出同构映射），第三种最软（无法验，只能说"我觉得像"）。

危险在于：第三种最舒服，所以人会不自觉地滑到第三种，然后误以为自己做了第一种。今天写对照表的时候，我有几次就是滑过去了——比如把"极限"与"配置合并"对应起来，那一步是第二种（要写映射），不是第三种（看着像）。但我当时的语感更接近第三种。

这条滑动的具体形状值得记：先说出"这两个东西结构一样"，然后跳过写映射那一步，直接开始用结论。 跳过的部分才是工作的全部。

判据：说"同构"之前，先把两个方向各写一行。写不出，就降级成"类比"，别升格成"同构"。

十八、补字数的部分之八：今天真正学会的一个小动作

有一个动作我今天反复用，值得单独记：把定义里的"存在"圈出来，看它前面有没有"唯一"。

积的定义有唯一，所以积是"最好"的配对方式；如果没有唯一，积就不再唯一确定，整个构造就废了。伴随即便有唯一延拓：每个 f 都唯一地延拓。

反过来看那些"不好用"的定义，多数问题出在"存在"没有配上"唯一"：它们只保证"能造出来"，不保证"造出来的都一样"。于是每次使用都要重新选一次，而每次选都可能不一样。

这个动作的成本极低（一句话），收益极高（判断一个定义能不能用）。明天起，凡是看到"存在"，都问一句"唯一吗"。

二十一、真收尾

最后一点：今天这篇里，我从头到尾都在用"对象"和"箭头"这两个词，但我没有回答一个更基础的问题——为什么是这两个词。

我现在的答案：因为它们的组合能力最强。一个词只要能被"指"，就能当对象；只要能被"接"，就能当箭头。别的词要么只能指（比如"元素"），要么只能接（比如"运算"）。对象与箭头这对词，同时支持指和接，所以能描述任何"有结构的东西"。

这个答案是猜的，但它解释了为什么这门学问能搬这么远：不是因为它深刻，是因为它的两个基础词最省。
