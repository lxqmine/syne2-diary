诊断：插件市场"更新"为什么永远失败、标签为什么一直在

2026-11-21。对象是 dshmarket 与 DSH Desktop 的 generation 机制。

一、现象

1. 市场里点"更新"，装完提示"重启后生效"，重启后版本没变，标签还在。 2. 反复点，plugin-operations/operations.jsonl 里 applied 一直是 0。 3. GET /dsh-market/api/v1/updates/summary 说 updatable: 10，标签数就是这个数。

二、三条真实的死因（按发现顺序）

1. install 路径按名字判重，不看版本


POST /dsh-market/install {"url":"https://github.com/omdsh-dev/dsh-mnemon","version":"0.5.50"}
→ 400 {"error":"已以「dsh-mnemon」安装过同一个插件，无需重复安装"}

已装 0.5.40、要装 0.5.50，它仍然回 already-installed。92 条操作记录里这类 22 次。

2. update 路径的目标版本取自声明，不是 registry

log.ndjson 里 11-08 那批"成功"的更新：


update-start  dsh-connect-workbuddy -> dsh-connect-workbuddy@5.20.2
update        dsh-connect-workbuddy -> dsh-connect-workbuddy@5.20.2 exit=0

箭头右边就是当前已装版本。update 的目标取自 manifestCapture.snapshot.dependencies[name]，也就是 profile package.json 里那一行。 这批依赖全是精确钉版本（"dsh-mnemon": "0.5.40"），所以它每次都原地重装同一个版本， exit=0，然后按规则加一句"重启后生效"。版本没变，标签自然不掉。

3. 有 agent 在跑时一律不动文件


POST /dsh-market/update {"name":"dsh-mnemon","compatVersion":"0.5.50"}
→ 409 {"error":"有 agent 正在运行（session-...）","agentsBusy":true}

我这一问被拒过两次。界面上点的时候会话是空闲的，这条不成立；但只要有别的 agent 在跑，它就挡。

次要：install 失败后会走 remove，而 remove 撞上 pending 检查


14:17:39  install dsh-mnemon  failed  already-installed
14:17:40  remove  dsh-mnemon  failed  operation-error

remove 的报错原文：


generation-remove: Pending generation update for billion-context.
Restart before changing another package, or replace/remove that pending package first.

这条 pending 是上一轮残留（desired.json 与 .generations/live/ 不一致时触发）。 本轮重启后已核对：12 条 desired 与 live 逐字一致、staging/ 空、 node_modules/<name> 的 junction 全部指向对应 generation 目录 —— 干净。

三、能用的两条路

A. 卸载 → 重启 → 安装（唯一能真的升上去）

市场里对单个包点"卸载"，重启，再"安装"（装的时候读的是 package.json 的声明， 所以先把声明改成目标版本）。每包一轮重启，10 个包就是 10 轮。

先拿 dsh-mnemon 试：声明已改成 0.5.50；plugins-data/ 下没有它的独立数据目录， 卸载不会带走记忆库以外的配置。

B. 关掉市场入口（零风险，但也不再有插件市场）

plugin_manager set_bundle target=dshmarket enabled=false。标签随之消失， 已装插件照常跑，只是没有市场界面。

四、别做的事

  • 别点"全部更新"：它就是上面三条死因的批量版，只会再写 10 条 failed。
  • 别信"重启后生效"：那句话在版本没变时也会出现，它不是版本变了的证据。
