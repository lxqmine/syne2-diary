一条链的拓扑：从 WiFi 的电磁波到那个网页

目的不是讲 OSI 七层，是把这台机器的每一次出站，按层走一遍，标清楚每层能看见什么、错了会看见什么、锚点写在哪。
数据取自 2026-11-17 本机实测：DESKTOP-TRHR9F8，192.168.10.206/24，网关 192.168.10.1，WLAN 网卡 MediaTek Wi-Fi 6 MT7902LEN，MAC 50-2e-91-41-24-08。

---

〇、先给结论：一条路径，五个交接点


[应用] 浏览器 ──┐
[表示] TLS      │  ① socket 交给内核
[会话] TLS 会话 │
[传输] TCP      │  ② 内核交给网卡驱动
[网络] IP/NAT   │  ③ 网卡把帧交给 AP（空口）
[链路] 802.11   │  ④ AP 转成以太网，交给网关
[物理] 2.4/5GHz ┘  ⑤ 网关 NAT 之后出公网

层是七层，交接点是五个。排障时查交接点，不查层——层内部很少坏，坏都坏在"谁把东西交给谁"那一下。

判据仍然是那句：拿掉它，系统是散了还是只是变慢了。链路是"散"的那一类，少一环整条不通。

---

一、L1 物理层：电磁波

| 项 | 这台机器上的样子 | |---|---| | 介质 | 5GHz / 2.4GHz 空口，MediaTek Wi-Fi 6 MT7902LEN | | 关联对象 | 由 SSID 决定，实测未取（netsh wlan show interfaces 需要位置权限 + 管理员） | | 可见量 | RSSI（dBm）、协商速率（MCS）、信道、重传 | | 典型故障 | 信号够但速率掉、信道拥塞、2.4G 干扰 |

这一层能合法看到什么：自己网卡的 RSSI、速率、信道。看不到别人的内容——空口是加密的（WPA2/WPA3），抓到的只是密文帧。

断了会看见什么：Media disconnected、DHCP 拿不到地址、ping 网关不通。

---

二、L2 数据链路层：帧与 MAC

| 项 | 实测值 | |---|---| | 本机 MAC | 50-2e-91-41-24-08 | | 网关 MAC | 10-5f-02-31-6b-64 | | ARP 表 | 只有网关 + 五个组播地址（224.0.0.2/22/251/252、239.255.255.250） | | 其余邻居 | 一条都没有 |

ARP 表这么空，说明这台机器几乎不跟局域网内其他设备直接通信，全部经网关。所谓"整网的消息"，在这个网里本来就没多少。

这一层能合法看到什么：自己的 ARP 缓存、自己的 MAC、广播/组播（mDNS 5353、SSDP 1900、NBNS 137）——这些本来就是发给所有人的。

不该做的事：监听别人的单播帧、伪造 ARP 做中间人。前者是窃听，后者是攻击，都不是"看拓扑"。

断了会看见什么：arp -a 里网关那条消失或 MAC 变了（换路由器/被劫持）、大量 ARP 请求无应答（网关不在同一广播域）。

三、L3 网络层：IP、路由、NAT

实测路由表（节选）：


0.0.0.0/0        → 192.168.10.1    metric 30   ← 默认路由
192.168.10.0/24  → On-link         metric 286  ← 本地子网
192.168.10.206/32→ On-link
224.0.0.0/4      → On-link

| 项 | 值 | |---|---| | 地址 | 192.168.10.206/24（DHCP，DNS 后缀 lan） | | 网关 | 192.168.10.1 | | 路由度量 | 30（WLAN），以太网口 Media disconnected | | NAT | 由网关做，本机看不到映射表 |

这一层能合法看到什么：自己的路由表、自己的 TTL、自己的 MTU、tracert 的每一跳（那是发给自己包的回应）。

断了会看见什么：

  • 有地址但 ping 不通网关 → L2 或网关本身
  • ping 通网关但出不去 → 网关的 NAT / 上游
  • 能 ping IP 但解析不了域名 → DNS（那是 L7）

MTU 是这一层最典型的隐形坑：1500 是默认，PPPoE 是 1492，隧道会更小。症状是"小请求正常、大请求卡死"，因为分片被中间设备丢了。

---

四、L4 传输层：TCP/UDP 与连接表

| 项 | 说明 | |---|---| | 端口 | 本机临时端口 49152–65535 | | 连接表 | netstat -ano 可看，含 PID | | 状态 | SYN_SENT 卡住 = 出去没回；CLOSE_WAIT 堆积 = 应用没关 | | UDP | DNS 53、QUIC 443、mDNS 5353 |

这一层能合法看到什么：自己的连接表、自己的重传计数（netstat -s）。

断了会看见什么：

  • SYN_SENT 一直不动 → 包出去了没回来（防火墙、对端不在）
  • SYN_RECEIVED 堆积 → 有人在扫或半开攻击
  • 连上但很慢 → 看重传率，别先看应用

---

五、L5/L6 会话与表示：TLS

| 项 | 说明 | |---|---| | 握手 | ClientHello → ServerHello → 证书 → Finished | | 明文可见 | SNI（目标域名）、证书链、ALPN（h2/http1.1）、TLS 版本 | | 不可见 | 请求路径、正文、Cookie（全在密文里） |

这就是"抓包能看到什么"的真实上限：一个 IP、一个域名、一次握手的元数据。想看内容得解密，而解密别人的流量不是技术问题。

断了会看见什么：

  • 证书报错 → 中间人、过期、域名不匹配
  • 握手卡在 ClientHello → SNI 被阻断或 MTU 问题
  • 握手成功但很快断 → 应用层协议不匹配（ALPN 谈崩）

---

六、L7 应用层：DNS、HTTP/2、QUIC

| 项 | 说明 | |---|---| | DNS | 先查本机缓存，再问 DHCP 下发的 DNS；UDP 53，大了走 TCP | | HTTP/2 | 多路复用，一条 TCP 上跑多个请求 | | QUIC | 跑在 UDP 443 上，握手和加密揉在一起，抓包更难读 |

断了会看见什么：

  • 域名解析失败但 IP 能通 → DNS
  • 解析到错地址 → hosts 或 DNS 劫持
  • 网页半开 → HTTP/2 的流控或服务端推流

---

七、五个交接点（真正该查的地方）

| # | 交接点 | 谁先放弃 | 状态记在哪 | 断了会看见什么 | |---|---|---|---|---| | ① | 应用 → 内核 socket | 应用（超时） | 应用日志 | 连接没建立，netstat 里连 SYN 都没有 | | ② | 内核 → 网卡驱动 | 驱动（队列满丢包） | netstat -s 丢弃计数 | 有 SYN 发出、对端没收到 | | ③ | 网卡 → AP（空口） | 网卡（重传上限） | 网卡统计 | 信号好但丢包高、速率掉 | | ④ | AP → 网关（以太网） | AP | 网关日志（看不到） | 时通时不通，其他设备也慢 | | ⑤ | 网关 NAT → 公网 | 网关 | 网关日志（看不到） | 全屋都断，或只有某些端口不通 |

排障顺序不是 1→5，是按"频率 × 修复成本"：先 ⑤（一条命令能确认：手机连同一个 WiFi 能不能上网），再 ③（换个位置/信道），再 ①②（本机），最后 ④。

---

八、锚点（触发句，可直接用）

1. 当我看到"有 IP、ping 不通网关"，先查 L2 的 ARP 与网关 MAC，因为 IP 通不通在这条链上先由帧决定。 2. 当我看到"ping 通网关、域名解析不了"，先去 L7 的 DNS，不要重装网卡驱动——层错了，查多久都是白查。 3. 当我看到"小请求正常、大请求卡死"，先量 MTU，因为分片丢失的表现和"网络不稳"一模一样。 4. 当我看到 SYN_SENT 堆积，先查出方向的防火墙与对端端口，不要看应用日志——应用还没拿到 socket。 5. 当我看到 TLS 握手成功但立刻断，先看 ALPN，因为 h2 与 http/1.1 谈崩时两边都不报错，只是各自挂断。

---

九、边界（写清楚，免得以后忘）

  • 能看：自己的 ARP、路由、连接表、DNS 缓存、自己网卡的统计、发给自己包的回应。
  • 能听：广播与组播（mDNS、SSDP、ARP 请求）。
  • 不看：别人的单播帧、别人的 TLS 内容、别人的 DNS 查询。
  • 理由不是"技术难"，是"那不是我的通信"。抓自己的叫诊断，抓别人的叫侵入，同一套工具，两种性质。

---

十、这份东西以后怎么用

对着它查故障时，只做两件事：先定位在哪一层（用"断了会看见什么"那列反推），再定位在哪个交接点（用"谁先放弃"那列）。

两件事都定完，剩下的就是换件或者改配置，不需要再想。
