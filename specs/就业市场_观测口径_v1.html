就业市场观测口径 v1

写于 2026-11-27，BOSS 直聘接入过程中。目的：说清"求职环境"这件事到底用哪几个数看，免得拿一个失业率当结论。

一、总量层（官方，匿名可取）

akshare.macro_china_urban_unemployment()，月度，字段为 日期/项目/值。四条序列：

| 序列 | 2026-10 | 近 13 个月区间 | |---|---|---| | 全国城镇调查失业率 | 5.1% | 5.0–5.4，首末差 0.0 | | 本地户籍劳动力 | 5.2% | 5.0–5.4 | | 外来户籍劳动力 | 4.9% | 4.6–5.3 | | 25–59 岁劳动力 | 4.1%（2026-08） | 4.1–5.0 |

读法：总量平（13 个月净变化 0），所以"求职难"的感受不可能来自总量，只能来自结构——岗位在哪些行业、要什么门槛、给多少钱。

二、结构层（BOSS 直聘，需过风控）

接口 https://www.zhipin.com/wapi/zpgeek/search/joblist.json，参数 scene=1&query=&city=&page=&pageSize=。

风控两关： 1. __zp_stoken__ cookie（由页面 JS 依 seed 算出，不能手工拼）； 2. IP 信誉（code 35 您的IP地址存在异常行为，与 UA/headless 无关）。

所以取数流程是：node tools/jobs/zhipin.mjs login（有头窗口人工过一次验证 → 存 cookie）→ report <关键词> <城市>。

要拿的五组字段：

| 字段 | 为什么是关键 | |---|---| | totalCount | 岗位存量。同一个关键词两个月对比，等于"这个岗位在不在收紧" | | salary 的 P25/P50/P75 | 薪资分布，比平均值有用：中位不动而 P75 掉，说明高端岗位先没 | | jobExperience | 经验门槛分布。1–3 年占比上升＝企业不愿培养，只要即插即用 | | jobDegree | 学历门槛。本科以上占比上升＝同一岗位在提门槛 | | brandIndustry / brandScaleName | 谁在招。中小企业占比下降＝招聘由大厂撑，是收缩期的典型形状 |

三、判据

1. 算"岗位数 ÷ 求职人数"没有分母（BOSS 不给求职者数），所以只能看同一关键词的月度变化，不看绝对值。 2. 薪资中位数与失业率必须一起看：失业率平、薪资中位下行 = 有工作但在降薪；两个一起恶化才是真冷。 3. 单一平台有偏（BOSS 偏互联网与中小企业），所以结论只能写"BOSS 口"，不写"全市场"。 4. 每月的快照必须落盘（knowledge/就业/<YYYY-MM>.json），否则下个月没有对比基线——这个坑和社交平台一模一样。
