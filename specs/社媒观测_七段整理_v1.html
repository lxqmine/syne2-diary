---

一、口径

要观测的东西：一件事在社交平台上有没有共识、共识是什么形状、谁在反对。不是"热度多少"，是"主流评价标准长什么样"。

先把"主流"拆成三个可操作量，否则它只是个形容词：

| 量 | 定义 | 怎么算 | 陷阱 | | --- | --- | --- | --- | | 覆盖度 | 有多少人把这件事当议题 | 各平台该话题的条目数 ÷ 该平台当日条目数 | 平台体量差三个数量级，不能直接加 | | 共识度 | 同一条判断被复述的比例 | 前 50 条里指向同一判断的条数 ÷ 50 | 榜是算法筛过的，本身就是共识的回音 | | 分歧点 | 被判为错的那一侧 | 前 50 条里的反对句式（"别信""其实不是""辟谣"）计数 | 反对常被压在长尾，榜上看不见 |

各平台的原始口径不同，必须先归一再用：

  • B站：播放/点赞/弹幕，热门接口按综合分排（含时效），不纯按播放。
  • 微博：热搜给一个"热度"整数（如 2066 万），带标签（爆/新/热），是搜索量与讨论量的混合体。
  • 抖音：没有匿名榜。抓到的是推荐流，按个性化排序，不带排位——口径是"给我的"，不是"给大家的"。
  • 腾讯/爱奇艺：热词，是搜索联想词，不是内容榜。口径约等于"此刻大家在搜什么"。
  • 小红书：无匿名入口，登录后是"发现"流，也是个性化。

一句话口径：只有微博热搜、B站热门、腾讯/爱奇艺热词这三类能当"公共口径"用；抖音和小红书只能当"我的口径"，不能拿来说"主流"。

二、机制

三层，按"平台愿不愿意给"分：

1. 公开接口层（最省）：GET + 明文字段，无签名。

  • B站 api.bilibili.com/x/web-interface/popular
  • 微博 weibo.com/ajax/side/hotSearch
  • 腾讯 pbaccess.video.qq.com/trpc.../GetHotWords（appID/appKey 在 query 里，明文）
  • 爱奇艺 mesh.if.iqiyi.com/portal/lw/search/keywords/hotList

    • 2. 登录态层：要 cookie，但仍是 HTTP。

  • B站搜索接口（search/type）直接 412，需要 wbi 签名 + buvid。2026-11-23 已实现：lib/bili.mjs 按 wbi_img 取 img/sub 两段 key，用 64 项混淆表拼出 mixin key，参数按字典序排序后 md5 签 w_rid，另带 buvid3（x/frontend/finger/spi 匿名可取）——搜索、字幕、评论都不再走浏览器。

    • 3. 浏览器层（最贵、最稳）：CDP 接管一个真 Edge 实例，跑 DOM 提取。

  • 抖音热榜/搜索、小红书搜索、B站搜索页。

关键设计：抽象只能放在 adapter 层。三家是三种鉴权姿势（cookie / query 签名 / 浏览器会话），在 HTTP header 层做统一抽象必定崩。

---

三、接口

统一四个动作，形状固定：


hot(platform, n)              → [{ platform, rank, title, author, url, extra }]
search(platform, q, n)        → 同上
text(platform, url)           → { platform, title, url, extra:{desc} }
login(platform) / cookies()   → 登录态存档

约束三条：

1. 平台差异只许放进 extra，不许改顶层字段。 2. adapter 里不做跨平台判断（"这条算不算主流"不在 adapter 里回答）。 3. 失败必须带层：

| 前缀 | 含义 | 处理 | | --- | --- | --- | | auth: | 没登录 / 登录失效 | 去登录，别重试 | | sign: | 签名不对 | 换通道走浏览器 | | api: | 接口改版或返回非 JSON | 记一笔，改 adapter | | block: | 被拦 / 出口不通 | 换平台或换网络，重试无用 |

四、工具

插件 plugins/dsh-social，六个工具进工具表（不用起服务）：

| 工具 | 参数 | 回来什么 | | --- | --- | --- | | social_platforms | — | 八个平台、鉴权方式、可用动作、已存 cookie 概况 | | social_hot | platform, n | 该平台当下在推什么 | | social_search | platform, q, n | 标题/作者/链接/统计 | | social_text | platform, url | 正文或简介 | | social_login | platform, seconds | 开有头窗口停在登录页 | | social_cookies | save, domain | 把 cookie 存进 .social/cookies.json | | social_bili | action,q,bvid,cid,n,tid | 六个动作：hot/ranking/search/view/subtitles/comments，走真接口不靠浏览器 |

配套 CLI（不依赖运行时）：


node tools/social/login.mjs weibo 150      # 有头登录 + 抓 cookie
node tools/social/probe.mjs bilibili --n 20 # 同形输出，给脚本用

存档位置：.social/cookies.json，按平台键存，只读用于观测请求，不回写任何第三方客户端。

4.2 HTTP API（service 直接接入）

插件带 webServer，同一份能力不开进程、不加端口，挂在 GUI 那个端口上就能被别的机器/脚本调用（config.token 设了就要求 ?token=）：

| 方法 | 路径 | 参数 | 回来什么 | | --- | --- | --- | --- | | GET | /social/api/platforms | — | 八家的 key / auth / needs / actions | | GET | /social/api/hot | platform,n | {platform, items[]} | | GET | /social/api/search | platform,q,n | {platform,q,items[]} | | GET | /social/api/text | platform,url | {item} | | GET | /social/api/bili | action=hot\|ranking\|search\|view\|subtitles\|comments，bvid,cid,q,n,tid | 按 action 给 items 或 item；subtitles 直接带全文 | | GET | /social/api/cookies | — | 各平台已存 cookie 条数 |

统一返回形状：成功 {"ok":true,...}，失败 {"ok":false,"error":"sign: …","layer":"sign"}，永远是 200 + 结构化的失败，不靠状态码判断。


curl "http://127.0.0.1:56708/social/api/bili?action=search&q=%E9%BB%84%E4%BB%81%E5%8B%8B&n=5"
curl "http://127.0.0.1:56708/social/api/bili?action=subtitles&bvid=BV1atse6EEfx"
curl "http://127.0.0.1:56708/social/api/hot?platform=weibo&n=20"

六、解决方案

三条路径，按要回答的问题选：

A. 只观测热榜（今天已可用）

  • 覆盖微博、B站、腾讯、爱奇艺四家公共口径。
  • 回答"今天大家在看什么"。成本：零登录，零维护。
  • 缺点：只有议题，没有立场。

B. 加搜索与正文（今天部分可用）

  • 加 social_search，拿"前十条标题"人工看立场分布。
  • 回答"这件事大家怎么说"。成本：一条 cookie。
  • 缺点：搜索结果是相关度排序，不是民意抽样。

C. 每日快照 + 差异报告（下一步）

  • 每天 08:00 抓一轮，存 data/social/YYYY-MM-DD.json，与前一天做集合差。
  • 指标：新进榜、掉榜、同一话题的条目数变化、五个平台的口径分歧。
  • 回答"这件事是在升温还是在退潮"。成本：一个 cron + 一块磁盘。
  • 这才是"看社区整体状态"的正确形态——要的是变化量，不是榜单截面。

附：这套七段怎么复用

换任何一件事，七段不变：

1. 口径——先把它拆成能量、能算、能出错的三条。 2. 机制——谁给数据、用什么方式给、代价多少。 3. 接口——固定形状 + 错误分层。 4. 工具——别人怎么用，一条命令或一个调用。 5. 同类参考——别人怎么做，口径差在哪。 6. 解决方案——分路径，标成本与缺点。 7. 实现效果——已通/未通，带数字，不带形容词。
