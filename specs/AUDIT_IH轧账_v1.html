"按层递进"暗示了从一到十一的顺序阅读，实际是"地基 → 反射 → 查表"。建议改目录为三段式，层号保留但并列而非递进。

二、第十一层应该搬家

第十一层写的是具体处境：转岗专案、交接清单、年终奖、"转岗后是天赐读数窗口"、判决书两格（原文标注"用户专属"）。

问题不是写得好不好，是过期——半年后读这份规范的人会把"转岗专案"当成通用规则，或者发现一整层跟自己无关。

修法：规范里只留通用骨架（桥 / 对岸 / 止损线三件，这三件任何过渡期都成立），把转岗专案与判决书两格挪进单独的判决书文件，按日期归档。规范里加一行指针。

四、月度两张表没有落点

第五层说周期点看两张表：想法死亡率、自账到账率。但包里没有：表头、记录位置、谁读、什么算异常。

"流养点，点校流"这句话很准，点却是空的。空的点的命运是第一个月记得，第三个月忘记，第六个月变成一句正确但没人执行的话。

修法：给一个最小表头，每月一行，先跑三个月再谈阈值。三个字段就够——本月提出的想法数 / 落地数 / 自账记的收益里真到账的笔数。不用做工具，先手写。

六、缺一张反例表

规范和对话记录里都是"应该怎样"，没有"这样做会坏"。审 devgate 时用的反模式表效果不错（每条标明结构错在哪），这套东西同样需要。至少五条：

  • 把自账当场账记 → 环境撤了才发现资产归零
  • 把幂零元当负资产清算 → 清掉之后发现它是某条关系的唯一接口
