接口层统一设计 v1

口径：用 Web 开发的接口层术语，自上而下拆链路（request path）/ 网关（gateway）/ 端点（endpoint）/ 鉴权（auth scheme）/ 错误模型（error model）/ 实现映射（implementation mapping）。
每一条断言后面必须跟证据（response header、HTTP status、字节数、Probe Log 日期）。没有证据的写【未验】。
各平台细节见 平台参考/<platform>.md；本文只写跨平台那一层。

---

0. 结论先行

1. 八个平台，六种鉴权姿态：匿名（抖音热榜、微博热榜、腾讯/爱奇艺热词）、visitor cookie（微博正文）、session cookie（B站 SESSDATA、小红书 web_session、抖音 sessionid）、请求签名（B站 wbi、抖音 Argus、小红书 x-s）、OAuth 2.0 Bearer（westock）、不可达（YouTube/X，出口层）。 2. 抽象只能在 adapter 层做，因为签名与 cookie 的注入位置各家不同：B站签在 query（w_rid+wts）、抖音签在 query（a_bogus）且要求 uifid 头、小红书签在请求头（x-s/x-t）。统一到 header 层会立刻破。 3. "HTTP 200 就是成功"在这个层是错的。三家把业务状态放在三处不同位置：header（Bili-Status-Code）、body envelope（ok/errno/code）、以及"200 + 空 payload"的降级形态。 4. 判"能不能接"的顺序是：先看链路可达（DNS/TLS/出口）→ 再看网关是否要签名 → 再看鉴权 → 最后看业务码。跳过前三步直接写业务逻辑，就会把 412/432 当业务错误。

---

1. 链路：一个请求经过哪五层

| 层 | 职责 | 典型实现 | 判定证据（response header） | | --- | --- | --- | --- | | L0 DNS / TLS | 域名解析、证书 | 公共 DNS、CDN 边缘证书 | server、证书链、【未验】 | | L1 CDN / edge | 缓存、回源 | X-Cache-Webcdn（B站）、X-Cache-Lookup（腾讯） | x-cache-*、age、expires vs date | | L2 WAF / anti-bot | 拦截自动化、验证码、指纹 | 抖音 Argus、微博 visitor 校验、B站 412 | 403 纯文本（字节数可判）、412、432、302 → /login 或 SSO | | L3 API gateway | 路由、限流、配额、鉴权前置 | APISIX（新浪 westock）、Envoy（爱奇艺 x-envoy-upstream-service-time、x-b3-traceid）、Skywalker（爱奇艺 server: Skywalker/3.10.1）、TLB（抖音 server: TLB）、自研 trpc 网关（腾讯） | x-envoy-*、x-b3-*、x-ratelimit-*、x-trace-id、server、via | | L4 upstream service | 业务实现 | B站 api.bilibili.com、微博 mapi 集群 | 内网主机名泄漏（微博 Ssl_node: mapi-10-54-7-26.hj4.intra.weibo.cn）、x-upstream-ip（腾讯） | | L5 response envelope | 业务码与错误信封 | code/message/data、ok、errno、ret+msg、data.errorCode、Bili-Status-Code | body 结构 + header 业务码 |

用法：任何"接口不通"，先按 L0→L5 逐层排除，不要从 L5 往上猜。现成的反例：B站 x/web-interface/search/type 的 412 是 L2 拒的（缺 wbi 签名），不是 L4 说"你没权限"。

2. 网关：谁在路由，谁在限流

| 平台 | 网关形态 | 证据 | 对客户端的影响 | | --- | --- | --- | --- | | B站 | 自研网关 + edge 缓存（blzone） | X-Cache-Webcdn: BYPASS from blzone05、Bili-Status-Code、Cpu_usage | 业务码与 HTTP 码分离，必须读头 | | 微博 | 内网 LB（Lb、PROC_NODE）→ mapi 集群 | body/header 泄漏内网主机名、XSRF-TOKEN 下发 | 三个域三套信封（ok / ok:-100 / errno） | | 抖音 | TLB → Argus（WAF 层）→ 业务 | server: TLB、x-tt-trace-id、x-janus-info、bd-tt-error-code | 签名在 query（a_bogus、msToken、verifyFp），header 只带 uifid | | 小红书 | 网关 → 登录校验前置 | 302 → /login、code:-101 | 登录校验先于签名校验，无 session 时签名对错无法验证 | | 腾讯视频 | trpc 网关（/trpc.<pkg>.<svc>.<method>/<method>） | appID/appKey 明文 query、x-nws-log-uuid、两套信封（{"ret":0} / {"data":{"errorCode":0}}） | 老接口新接口并存，不能统一处理 | | 爱奇艺 | Envoy 网关（mesh.if.iqiyi.com） | x-envoy-upstream-service-time、x-b3-traceid、x-ratelimit-limit-1: 20000 / remaining-1 | 配额是显式的，可以据此做退避 | | westock | APISIX 3.3.2 + OAuth 2.0 授权服务器 | server: TAPISIX/3.3.2、WWW-Authenticate: Bearer resource_metadata=…、/.well-known/oauth-authorization-server | 标准 MCP 流程，先 token 后调用 | | YouTube / X | 不可达 | 全部 status=000（含三个镜像） | 不是鉴权问题，是出口问题，抛 block: |

网关层要抓的三件事：①限流窗口与配额（x-ratelimit-*、Retry-After）；②签名/鉴权在哪一层判（L2 还是 L3）；③错误信封的归属（header / body / status）。

3. 鉴权：六种姿态与判定表

| 姿态 | 凭据 | 注入位置 | 缺失时的表现 | 平台 | | --- | --- | --- | --- | --- | | anonymous | 无 | — | 直接可用 | 抖音热榜、微博热榜、B站热门/排行/详情、腾讯/爱奇艺热词 | | visitor cookie | SUB+SUBP（匿名签发） | Cookie | 302 → passport.weibo.com/visitor/visitor，头 X-Login-visitor: true | 微博正文、微博信息流 | | session cookie | SESSDATA（B站）、web_session（小红书）、sessionid（抖音） | Cookie | B站 -101 账号未登录；小红书 302；抖音仍卡签名 | B站关注/历史/字幕增强、小红书全站、抖音详情 | | request signing | B站 wbi（w_rid+wts）、抖音 a_bogus、小红书 x-s | query（B站/抖音）、header（小红书） | B站 412 或 -352；抖音 403+46B/50B 纯文本；小红书 code:-101 | 搜索、空间、播放 | | OAuth 2.0 Bearer | access_token（+refresh_token） | Authorization: Bearer | 401 + WWW-Authenticate: Bearer resource_metadata=… | westock | | 不可达 | — | — | status=000 | YouTube、X |

三条判据（比"试一下"快）：

1. -352 → -403（B站）：签名补对了，权限不够；仍 -352 就是签名没对。 2. 46 字节 vs 50 字节纯文本（抖音）：Uifid Not Found 是缺 header，Signature Not Found 是缺签名——两级门槛可分机器判别。 3. 签名前先问登录（小红书）：登录校验先于签名校验，没有 web_session 时"签名对不对"这个问题无法回答。

签名可离线复算的只有一个：B站 wbi（md5(query + mixinKey)，mixinKey 由 wbi_img 两张图的文件名重排取前 32 位）。抖音 Argus、小红书 x-s 无浏览器算不出，必须走 CDP 兜底——这是选择 auth: 'browser' 的唯一正当理由。

4. 端点：按"资源域 × 鉴权姿态"编排

一行一个 endpoint，必填 Idempotent 与 Auth scope。样例（完整表在 平台参考/<platform>.md 第 4 节）：

| Platform | Method | Path | Auth scope | Idempotent | Purpose | | --- | --- | --- | --- | --- | --- | | bilibili | GET | /x/web-interface/popular | anonymous | yes | 热门视频 | | bilibili | GET | /x/web-interface/wbi/search/type | signing (wbi) | yes | 搜索 | | bilibili | GET | /x/player/wbi/v2 | anonymous (degraded) | yes | 字幕清单，匿名回空数组 | | bilibili | GET | /x/v2/reply | anonymous | yes | 评论（oid 必须是 aid，sort=2 按热度） | | weibo | GET | /ajax/side/hotSearch | anonymous | yes | 热搜 | | weibo | GET | /ajax/statuses/show | visitor SUB | yes | 单条正文 | | douyin | GET | /aweme/v1/web/hot/search/list/ | anonymous | yes | 热榜 51 条 | | douyin | GET | /aweme/v1/web/comment/list/ | signing (Argus) | yes | 评论，需 uifid + a_bogus | | tencent | GET | /trpc.universal_backend_service.hot_word_info.HttpHotWordRecall/GetHotWords | anonymous（appID+appKey 明文） | yes | 热词 | | iqiyi | GET | /portal/lw/search/keywords/hotList | anonymous | yes | 热词 | | westock | POST | /cgi/cgi-bin/openai/mcp/mcp | Bearer | depends | MCP JSON-RPC（initialize / list / call 三个 MCP 方法） |

编排规则：同一资源域下，把 anonymous 的端点排在前面，signing 的放后面——失败时降级路径天然存在（热榜挂了还能搜，搜索挂了不能假装有热榜）。

5. 错误模型：三层错误必须能分开

| 层 | 表现 | 判定 | 客户端处理 | | --- | --- | --- | --- | | 链路层 | DNS 失败、TLS 失败、status=000 | fetch 抛错 / 无响应 | 抛 block:，不重试 | | 网关层 | 401/403/412/429/432、Retry-After、x-ratelimit-remaining-1: 0 | HTTP status + 限流头 | auth: 或直接退避 | | 业务层 | 200 + 业务码非 0（code/ok/errno/ret/Bili-Status-Code） | 信封字段 | 抛 api:，附业务码 | | 降级 | 200 + 业务码 0 + 空 payload / null | payload 结构，不是 status | 抛 api:（degraded），不要当空结果 |

统一错误前缀（实现侧）：auth: sign: api: block:。这四层是可机器判别的，不要用"请求失败"四个字糊过去。

---

6. 实现映射与约束

  • Adapter 契约：meta{name, auth, needs, actions} + hot/search/text（+ 平台特有动作），失败抛带层错误。
  • 代码：plugins/dsh-social/lib/{browser,bili,platforms}.mjs；HTTP 面 /social/api/{platforms,hot,search,text,bili,cookies}；工具面 social_*。
  • 三条硬约束：①返回形状只在 extra 里扩，不改公共字段；②adapter 内不做跨平台判断；③签名/鉴权失败的抛错必须带层，便于上层决定是重试还是换路。
  • 浏览器兜底只给两种场景：签名算不出（抖音 Argus、小红书 x-s）、以及 DOM 是唯一数据源（无 endpoint 暴露，product-level absence）。

8. Probe Log 口径

一行一条：date | method + URL | HTTP status | app code | note。判据必须可复现：贴 curl 命令或 CDP 片段，不只写结论。失败记录不删——46 字节与 50 字节的差别就是失败记录换来的。
