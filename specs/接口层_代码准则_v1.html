0. 一句话

一个能力在代码里只活一份。多一份，就多一个漂的方向。

"写的时候小心"不是判据。判据是：违反了，能用一条 grep 抓出来。

2. 根：一次迁移只做了一半

README §结构 画的是声明式结构：clients/<平台>/{platform.json, src/{endpoints,auth,index}.mjs} + lib/{loader,engine,session}.mjs，"加一个平台不改引擎、不改 index.js"，平台清单只有一个来源。

代码里还活着一套手写栈：

| 栈 | 文件 | 平台清单从哪来 | 服务哪些入口 | | --- | --- | --- | --- | | 声明式 | lib/engine.mjs + clients/* | lib/loader.mjs 扫目录，9 家 | social_<p>_api、social_call、/social/api/{endpoints,call} | | 手写 | lib/platforms.mjs，347 行 | 文件里写死 8 个对象 | social_hot/search/text、social_bili、/social/api/{hot,search,text,bili,platforms} |

于是同一件事有两份：

  • 平台清单：plats.meta() 8 家（platforms.mjs:321，无 westock）；loader 9 家。social_platforms（index.js:53）看到 8 家，social_endpoints（index.js:275）看到 9 家。加一个平台只加一半，两个工具就开始说不同的话，且都不报错。
  • 错误层：engine.mjs:78-84 412→block:、432→auth:、403 按响应体字节分 sign:/auth:；platforms.mjs:25 401/403/412/432 一律 auth:。同一个 403，走 social_search 是 auth:，走 bilibili_api 是 sign:。
  • cookie 罐：session.mjs:22-33 的 cookieHeader()；platforms.mjs:31-45 的 biliJar()。
  • 微博 visitor：session.mjs:49-69（落盘、Chrome141、正则取 tid）与 platforms.mjs:102-132（内存 12h、Chrome131、JSON 取 tid）。

这不是几个 bug，是一条根长出来的一整片枝。先定留哪套，后面五节才有意义。

目标只有一条单向依赖：


index.js（tool 壳 / HTTP 壳：取参、序列化）
  → lib/semantic.mjs（hot/search/text：归一化）
    → lib/engine.mjs（拼 URL、发、读信封）
      → clients/<平台>/（签名、cookie、状态码特例）
lib/constants.mjs（UA、默认条数、超时、端口）——谁都能读，不许写

反向依赖一处都不许有：clients/* 不 import engine，engine 不 import clients/*，semantic 不认平台名。

3. 交互接口：两面一芯

规则三条：

1. 动作表只写一次。tool 面和 HTTP 面都读同一张表。 2. 参数 schema 只写一次。apiParams（index.js:228-241）是唯一一份，HTTP 面从它派生。 3. 成功/失败形状只写一次。两面返回同一对象，差异只在渲染：tool 出文本，HTTP 出 JSON。

现状：social_bili（index.js:129-163）和 /social/api/bili（index.js:374-393）各写了一遍六路 action 分派，且已经漂了——没字幕时 tool 回"没有字幕（可能没登录，或该视频无 AI 字幕）"，HTTP 回 {languages:[], text:''}。加第七个 action 要改两处，改一处就等于制造一个"只在某个入口错"的 bug。

参数面也不齐：tool 面 apiParams 收 method/params/body/form/path/rpc；HTTP /social/api/call（index.js:407-410）只把 query 塞进 params。同一个 endpoint，从 HTTP 调不了 POST body。 这不是"没实现"，是两面各写了一份导致的形状缺失。

4. 职责分离：谁可以认识谁

| 层 | 只许认识 | 不许认识 | | --- | --- | --- | | index.js | 参数、文本、JSON | 平台名、状态码、URL | | semantic | hot/search/text 的语义 | 平台名、签名算法 | | engine | spec 的字段、信封字段 | 哪家平台、签名细节、字节阈值 | | clients/<p> | 自己这一家的签名/cookie/状态码 | 别的平台、engine 内部 | | constants | 被所有人读 | 业务 |

现成的越界四处：

  • engine.mjs:81-84：bytes <= 48 ? 'uifid' : bytes <= 56 ? 'signature' —— 抖音两级门槛写进通用引擎。而且 spec（接口层_统一设计_v1.md §3）记的是 46/50 字节，代码是 48/56。同一条判据两个数，引擎里那个还错着。
  • engine.mjs:15-18：HEADERS_OF_INTEREST 混装通用头（content-type）、B站头（bili-status-code、x-bili-*）、抖音头（x-ms-token）、限流头。应拆"通用 + spec 自带"。
  • engine.mjs:28-29：if (typeof client.invoke === 'function') —— 给 westock 的 MCP 开逃生舱。协议不同是一等公民，不该是引擎里的一个 if。
  • platforms.mjs:15-28：getJson() 自带一套错层映射，和 engine 并列。两套映射表 = 同一个错误两种说法。

5. 常量统一：数副本

诊断_副本与覆盖_v1.md 管的是同一个值被抄两份（回写覆盖、空值冲默认、半份配置）。这一节是它的第四形态：同一件事被写两遍，然后各自演化。

| 值 | 副本位置 | 现状 | | --- | --- | --- | | UA | session.mjs:7（141+Edg）、platforms.mjs:9（131）、bili.mjs:5（140+Edg）、browser.mjs:14（131） | 四份、三个版本、五个指纹 | | 端口 9227 | index.js:26,191、browser.mjs:11、dy.mjs:9、dy-tool.js:23、cordis.patch.yml:7 | 六处 | | profileDir .tmp/edge-profile | index.js:26,192、browser.mjs:11、dy.mjs:9 | 四处（README 还有一处说明） | | 默认条数 20 | index.js:73,90,360,366；platforms.mjs 12 处；bili.mjs:127,148,160,224 | 二十处 | | 超时 | engine.mjs:67 15000；platforms.mjs 9000/10000 | 三个数，无出处 | | 平台清单 | platforms.mjs:321、clients/*/platform.json | 8 vs 9 | | auth 词表 | platforms.mjs 的 cookie/none/browser/proxy；platform.json 的 cookie+wbi | 两套枚举 | | endpointCount: 16 | clients/bilibili/platform.json:12 | 派生值手写 |

最后一条最像小聪明：endpoint 数量本来能算，抄进 json 就成了第二个真相，加一条 endpoint 它就开始说谎。

规则：常量进 lib/constants.mjs；平台常量进 clients/<p>/；派生值不落盘。 判据是 grep 命中数 = 1（唯一例外是"读取处"）。

6. 业务清晰：一套语义

  • 错误层只认字段，不认字符串。 engine.mjs:6 已经给 e.layer 赋值，index.js:345 却用 msg.split(':')[0] 反解。message 里带一个冒号（api: 未知 endpoint a:b），层就解析错。改成读 error.layer，字符串只给人看。
  • HTTP 状态别一律 200。 index.js:346 成功失败都回 200 + {ok:false}，调用方无法用状态码分流，等于把 接口层_标准分层_v1.md §11 的四层前缀废掉。按层给：block:→502、auth:/sign:→401/403、api:→200+ok:false（或 422），并把 retryable 写进同一个信封。
  • 两种结果形状别混用。 platforms 回 {platform,rank,title,author,url,extra}，engine 回 {ok,appCode,status,bytes,body}。上层只能按入口分支判断。命名分开：call() 回 raw，hot/search/text() 回 item。
  • 成功也是语义。 platforms.mjs:209,293,300 把"200 + 空列表"抛成 api:，这是对的；engine 对 200 + 空 payload 只回 ok:true。两种口径要统一到"降级不当空结果"（接口层_统一设计_v1.md §5）。

7. 改的顺序（按收益/风险，不按好看）

1. 平台清单收成一个来源。 social_platforms 改读 loader 的结果（或让 loader 把 platforms.mjs 的语义动作补进 client）。验收：两个工具列出的 key 集合相等。 2. 抽 lib/constants.mjs。 纯机械：UA/端口/profileDir/默认条数/超时各留一份。 3. 合 action 分派。 一张表，tool 壳和 HTTP 壳都调它。 4. 抖音 403 阈值下移到 clients/douyin/src/auth.mjs，顺手把 46/50 与实际对齐。 5. 删 platforms.mjs 的重复栈，semantic 改成 engine 之上的薄层。这一步最大，必须在 1-4 之后、且有 smoke 可跑时做。

1-2 可以在没有冒烟的情况下做（改完 node -e "import('./plugins/dsh-social/index.js')" 就能验语法与导出）；3-5 必须能跑 smoke.mjs。
