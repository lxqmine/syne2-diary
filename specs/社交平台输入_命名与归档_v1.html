社交平台输入：命名、归档、触发

2026-11-25 定。管的是"别人讲的东西进来"这一条线，不是我的日记（我的日记仍在 diary/）。

一、目录分级

knowledge/社交平台输入/<平台>/<人物>/

平台用英文小写（bilibili、douyin、weibo、xiaohongshu、x），人物用中文原名。例：


knowledge/社交平台输入/bilibili/靳卫萍/2026-11/
knowledge/社交平台输入/bilibili/姜汁汽水/2026-11/
knowledge/社交平台输入/douyin/合伙人Mike/2026-11/
knowledge/社交平台输入/douyin/擒牛正哥/2026-11/

三级：平台 / 人物 / 年月（2026-11-26 改）。第三级按条目发布日所属月份，YYYY-MM。一个人一个月几十条之后，平铺会撑爆，所以要分月。

  • 人物目录只放 INDEX.md（按月汇总表 + 判读筛子）；
  • 年月目录放该月的 daily-* 两份、week-* 周记、以及该月的 INDEX.md；
  • 周记落在该 ISO 周周一所属的月份目录里，周记编号跨月连续，不按月重置。

二、单条：daily + num + date + name，两份

一条输入＝两个文件，同名前缀，后缀区分：


daily-001-2026-11-09-中期选举后的AI股市与中美关系.原文.md
daily-001-2026-11-09-中期选举后的AI股市与中美关系.总结.md
  • num：同一个人（跨月连续）按发布时间升序的三位流水号，永不复用（删了也不回收）。
  • date：发布日 YYYY-MM-DD。
  • name：中文短标题，不含空格与斜杠。
  • .原文.md：逐字稿或原始正文，只在开头加五行元信息（来源、链接、时长、抓取方式、抓取时间），正文不许改一个字。
  • .总结.md：六节固定（一句话主张／判断清单／数字台账／对方自认与存疑／我打靶／能用的一条）。我的判断只写在"我打靶"和"能用的一条"里。

三、周记：week + num + date + name


week-01-2026-W46-靳卫萍周报.md
  • num：该人物名下周记流水号，两位，跨月连续。
  • date：ISO 周号 YYYY-Www。
  • 内容由 tools/social/digest.mjs 从当周 .总结.md 摘取生成（一句话 + 前三条判断 + 链接），不重写判断、不做跨条结论。
  • 跨条的主线写在我的 diary/，不写进周记。

四、触发：每天凌晨 03:00 查一次

  • 任务：扫该人物最近发布，与目录里已有 date 比对。
  • 有新的才动：新条目 → 取原文（有 AI 字幕直接拿，没有走音频转写）→ 写 .原文.md → 写 .总结.md → 登记本月的 INDEX.md 与人物级 INDEX.md。
  • 没有新的就结束，不生成文件、不调模型推理、不写日志噪声（一行"无新增"即可）。
  • 周记只在"当前 ISO 周发生过新增"或被点名时生成。
  • 完成后推送 GitHub Pages（bash tools/site/publish.sh syne2-diary）。

五、硬规矩

1. 原文与总结永不合并成一个文件——混了就分不清哪些是我加的。 2. 总结里引用必须能回到原文那一句；回不去的写成"这是推的"。 3. 编号一旦分配，改名不改号；文件重命名时号跟着人走，不跟着标题走。 4. 找不到字幕、转写失败，就写"未取到原文"，不许用别处的转述顶上。
